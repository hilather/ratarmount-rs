# Changelog

## Unreleased

### Changes

- A FUSE mount point that is, lies inside, or is an ancestor of a folder being mounted (a positional folder or a `--bind` source) or of the `-w` overlay directory is now refused with exit code 2, before the overlay database and marker are created, before any fork or daemonize and before the FUSE mount. The check follows symlinks, bind mounts (whole folder or subdirectory, a bind hidden under a later mount, and a bind inside the folder that a FUSE mount would propagate into) and case or Unicode aliases. Such a mount used to deadlock the single-threaded daemon (and `ratarmount B` mounted `B` onto itself). The refused mount point is not created, unless it lies under a directory that indexing creates (for example `--index-folders`). Two layouts are only caught by a second check after the archives are opened and the `-w` directory is created (a not-yet-existing `-w` directory and mount point differing only by case or Unicode form on a case-insensitive filesystem, and an input directory created by `--index-folders`); there the empty `-w` directory (no database, no marker) and the index files written while opening the inputs remain, as after any later failure. Archive-file and URL inputs never conflict; `--no-mount`, `-u`, `find` and export-only runs are not checked.
- Bare `ratarmount <folder>` mounts at `<folder>.mounted` when the default mount point would be the folder itself (it used to mount the folder onto itself); `folder.d` still defaults to `folder` and `x.tar.gz` to `x`.
- An explicit mount point or `-w` path with a component that is a regular file, a symlink loop or not searchable, or a `-w` path that is a file, now fails at startup with exit 2 instead of at mount time with exit 1. A mount point reached through a dangling symlink whose target exists only after the `-w` directory is created still works as before.
- With `-w`, the overlay directory is created before `--hashes` and `--publish-index` run, so a publish failure can leave an empty overlay directory.
- FUSE unmount: `ratarmount -u`, the control socket `unmount` command and the in-mount `.ratarmount-control/unmount` file retry `fusermount3 -u` every 50 ms for about a second while the mount is briefly busy (desktop mount watchers such as gvfsd-trash and gvfs-udisks2-volume-monitor probe every new mount), instead of failing on the first `Device or resource busy`. A mount that serves a `:temp:` overlay or live commit and receives SIGTERM falls back to a logged lazy unmount (`fusermount3 -u -z`) if it is still busy after the retries; SIGINT only retries. The control-file `unmount` used to always fail because it unmounted inside the FUSE request that opened it; it now unmounts on its own thread, logs a failure and can be tried again. The control socket answers `error: …` and stays available when the unmount fails. If both the retries and the SIGTERM lazy unmount fail, the daemon logs an error and keeps serving. (#136)
- FUSE unmount follow-ups to #136: `fusermount3` on musl (Alpine) reports EBUSY as `Resource busy`, which is now retried too. A SIGTERM lazy detach logs once that it is waiting for open files to close, and the signal watcher keeps running after a failed lazy unmount so a later signal retries. Plain read-only and plain `-w` mounts (not only `:temp:` and live-commit ones), in the foreground, daemonized or with an export, now unmount on SIGTERM and SIGINT instead of leaving a dead (`ENOTCONN`) mount. With a file held open, SIGTERM takes about 1 s (the retry window) before the lazy detach. The control socket `unmount` answers `ok unmounted` reliably, and a daemonized mount serves the socket at all. The lazy-unmount log names the real flags and no longer claims a retry. (#137)
- `RUST_LOG=debug` (or any global `RUST_LOG` level) now takes precedence over `-d`; before, `-d`'s level replaced it and no DEBUG output appeared. Module directives such as `RUST_LOG=ratarmount_fuse=debug` are unchanged, `-d` still applies when `RUST_LOG` is unset or empty, and `ureq::unit` stays capped at warn. (#138)
- `ratarmount-csi` and `ratarmount-volume-plugin`: publishing the owner-only socket no longer replaces a socket that is already listening. Two concurrent starts on one path used to both succeed and leave the first daemon listening on an unlinked inode; the second now fails with `socket already in use`, as a plain bind did. Uses `renameat2(RENAME_NOREPLACE)`, so a filesystem or seccomp profile without it fails closed. (#117)
- `--commit-overlay` (and `-w` create-if-missing) on a bare relative archive name such as `t.tar.gz`, `t.tar.bz2` or `t.zip` staged its temp file in `$TMPDIR`; when that is on another filesystem than the archive (e.g. tmpfs `/tmp`), the final rename failed with `Invalid cross-device link (os error 18)`. The temp file is now created next to the archive (the current directory for a bare name). (#134)
- **The base an overlay records is what was opened (#133, round 6):** `base_kind` (`git`, `directory`, `archive`) and `base_location` (`local:` or redacted `remote:`) come from the source the factory actually served for the mount, `--lower` or verb, not from a path or URL guess. A bind-only mount, a composite (its first element), a bare repository, `RATARMOUNT_FORCE_GIT`, a `file://` URL, an HTTP/S3 archive and a torrent each record what they served; locations are compared redacted and a credential in the typed URL is never stored. Reopen, `--lower`, `overlay seal`/`pack`/`diff`/`verify` and `sandbox run` (its finish now gates the base before sealing) compare the kind under every digest kind, `--base-digest none` included, and refuse a base of another kind naming `--force-base-mismatch`. `none` is kind-only (nothing is walked, statted or hashed). `--base-digest none` accepts a remote or local copy of the same archive (location is ignored). A base that moved between local and remote agrees only when the record is strong and a supplied `--base-digest` (or an archive's cached digest) equals it. A forced base-kind change without a supplied digest drops the overlay to kind-only identity (`base_digest_kind=none`): later runs compare kind, not content, until you supply `--base-digest`.
- **Round-6 review fixes (#133):** a mounted base replaced by a symlink to another archive is refused by the commit check; a supplied `--base-digest` decides alone, so a cached digest no longer rescues a wrong one, and only an archive is rescued across local and remote; reopen confirms a strong archive with the same comparator as the other gates (a byte-identical copy with another mtime reopens) and an accepted move to a remote place drops the old stamp rows; an accepted `overlay pack` leaves the recorded rows and the sealed change set as they are (only a forced relocation rewrites them); a base without `://` in its typed text (`rclone+remote:path`, `restic:/repo`) and an existing `.torrent` path are judged by their classified location; a URL typed as `--index-file` is never recorded as an index path; offline `--commit-overlay` learns what it rewrites from a `stat` (no index is built or loaded, no sidecar is written).
- **Round-6 fix round 7E (#133), overlay database path:** a dangling symlink, directory or other non-regular entry at an overlay's database path is no longer read as "no database": offline `--commit-overlay` no longer commits it as a raw directory after recovering another archive's journal by inode, a first `-w` open no longer creates a database through a dangling symlink, and restamps, baseline refreshes and `--base-digest none` reopen checks no longer skip it.
- **Round-6 fix round 7E (#133):** every copy fallback publishes only over the exact stamp its gate checked. The plain-TAR provenance copy (`--commit-overlay-mode copy`, or `auto` with deletions) no longer re-stats the archive after the check, a copy after the commit's own rolled-back append compares the stamp the rollback left under the lock (not just device and inode), and offline gzip/bzip2/xz recompress and ZIP rebuild commits now refuse an archive another writer changed since the gate instead of publishing over it.
- **Round-6 fix round 7D (#133):** a commit whose archive changed after its gate (another mount's commit, `tar -r`, a touch) no longer falls back to a copy in `--commit-overlay-mode auto`, and `copy` mode refuses it too: the copy source must be exactly the gate's snapshot unless the commit's own append rolled back, so a copy can no longer publish (and `tar --delete` from) a file the gate never judged. A directory (or any non-regular file) at the overlay database path is an unreadable record that defers a mount's journal recovery instead of letting it run before the gate.
- **Round-6 fix round 7C (#133):** a failed journaled append is cleaned up under the archive lock it took, from its own record: it never recovers or copies over a journal another file left at the archive's name, a commit whose journal unlink, directory sync or row update failed (or whose journal moved with a renamed directory) is reported as committed-but-pending instead of success, and the copy fallback publishes only over the file the commit gate accepted while it is unchanged. Crash recovery finds a journal beside the archive's current name, refuses a complete locator whose journal is missing (instead of clearing it), and keeps a done locator whose journal may sit beside another name. A rollback whose mtime could not be restored (EPERM) restamps the recorded stamp when its journal started on that stamp, so the next commit is accepted; a journal's target is the recorded base only by path or by the same device and inode, never by matching stamps.
- **Round-6 fix round 5 (#133):** a refreshed commit token shares one keep-alive owner instead of chaining every predecessor (interval commits no longer grow memory or recurse on drop); a commit journal is applied only to the file it was started for, under every digest kind, for every commit target and for a raw overlay directory (the inode decides; the device number is only a hint across reboots); a consistent complete journal rolls forward and re-baselines the recorded stamp; the offline `--commit-overlay` classifier asks the factory's own dispatch (a local `.torrent` under `--features bittorrent` is a remote folder, `file://` is the local path, a bare repository is Git) and no longer stands in a parent-directory source; read-only lookups of a WAL sidecar (block-table loaders, the digest peek every gate runs, the `Recreate::Never` and rebuild probes) open it immutable when no `-wal`/`-shm`/`-journal` exists, so they create no side files beside the archive; a strong remote record confirmed over a local copy by the copy's cached digest now packs without `--base-digest` and `diff --hash --json` reports it as confirmed (the identity gate kept the evidence it had used); `overlay pack --force-base-mismatch` against a copy at another place writes rows for that copy into the bundle (it kept naming the old place); a forced reopen over an edited copy at another local place no longer re-baselines the recorded stamp or manifest from that copy; an accepted move of an archive base re-points (or drops) the recorded `base_index_path`.
- **Round-6 fix round 3 (#133):** the commit check compares the recorded kind under every digest kind and refuses an Unknown record, including offline `--commit-overlay`; a pending commit journal is applied only to the archive the overlay recorded (a foreign archive carrying its own interrupted-append journal is refused, archive and journal untouched, before recovery; offline `--commit-overlay` recovers only after the check); a symlink retargeted to another archive while the base is mounted is refused (the name and the inode must still match); consulting a `.tar.zst` or `.tar.bz2` sidecar's block table opens it read-only; `--commit-overlay --force-base-mismatch` is no longer blocked by a stale sidecar; the `--base-digest none` warning says the kind is still checked.
- **Overlays from v0.1.35 are unaffected:** an overlay without `meta` keeps remounting with no flag, and the first `-w` open records its kind, place and URL (no digest). Only an overlay written by an unreleased build (`format_version` 2 and no usable `base_kind`, for example the earlier `remote` kind) needs one `--force-base-mismatch`.
- **A commit checks the base before it writes:** live, interval, on-exit and `--commit-overlay` commits compare the archive's size and mtime with the rows the last create, commit or refresh wrote (a `stat`; the mount's `--base-digest` never overrides a changed stamp). A refused commit refuses only that commit (the mount keeps serving; `--force-base-mismatch` accepts the new base) and the interval logs it once per distinct stamp. A swap of the base with the same size and mtime cannot be caught without hashing; only `overlay verify` with a strong digest catches it (`overlay seal` of an already-strong base compares the stamp and does not rehash). `--commit-overlay` on a raw directory with no overlay database says no base identity was checked.
- **Library API (experimental):** `OpenBase`, `Opened`, `ClassifiedBase`, `SealedRecord`, `CreateOptions`, `ServedKind`, `ServedLocation` and `IndexProvenance` in `ratarmount-compositing`. `WriteOverlay::open(&ClassifiedBase, composed, dir, &CreateOptions)` replaces `WriteOverlay::new` and `new_with_create_info`; `overlay_seal::seal` takes the token and `reseal` takes the overlay's own `SealedRecord`; `commit_overlay` takes the token and `commit_overlay_raw_dir` is the separate entry for a directory with no database. Only the binary's factory wrapper implements `OpenBase` in production.
- **`overlay pack` temp files (#133, Robo-Ilya follow-up 3):** a killed pack left an empty anonymous `.tmpXXXXXX` (and a `.tmpXXXXXX` staging directory) beside the bundle. Pack now writes `.ratarmount-pack-XXXXXX.tmp` (holding an exclusive flock) and stages in `.ratarmount-pack-stage-*`, and the next pack in that directory removes dead ones: exact name shape, regular file (never a symlink), owned by the user, at least a minute old and unlocked. Leftovers named `.tmpXXXXXX` from earlier builds cannot be told from other programs' temp files and are not swept; delete them by hand.
- **Pack-temp sweep on platforms without an atomic no-replace rename (#133):** the sweep removes stale pack temps, copy files and orphan locks by first renaming them to a unique quarantine name with an atomic no-replace rename (`renameat2 NOREPLACE` on Linux, `renameatx_np EXCL` on macOS) and checking the inode. On platforms without one (e.g. BSD) a `linkat` + `unlinkat` fallback could delete a live file that replaced the stale one, so the sweep now skips them: stale pack temps are left for manual deletion there.
- **Interrupted `overlay import` (#133, Robo-Ilya follow-up 1):** a SIGKILLed import leaves a hot rollback `-journal`; `overlay info`, `fsck`, `seal` and `diff` used to fail with "attempt to write a readonly database". Reading an unsealed overlay whose database and directory are writable now rolls the journal back, so `fsck` reports `import_incomplete` and `seal` refuses by naming the import. A sealed or read-only overlay is never rolled back; the error says "an interrupted write left <db>-journal" and how to recover.
- **`overlay seal`, `overlay pack` and `diff` check the base (#133, Keystone 5564615409 blocker 1):** they run the cheap identity check reopen and `--lower` use (weak walk with the recorded exclusions, archive size/mtime, Git tree id; a strong record is also confirmed by `--base-digest` or by the digest already cached in the archive's index; nothing is hashed) and refuse a base that is not the recorded one, naming `--force-base-mismatch` (and `--base-digest` for a strong record). With `--force-base-mismatch` a seal records the base actually used (and `base_mismatch_forced_at`), a pack records it in the bundle only, and `diff --hash --json` reports it as `base` with `base_forced` and `base_recorded`. Both flags are experimental.
- **`--lower` accepts a copy of a strong base:** a bundle sealed against a strong digest is accepted over a byte-identical copy when `--base-digest` equals the recorded digest or the digest cached in the mounted archive's index does; the mount still never hashes.

- **Gate-3 fixes (#133):** the verified-bundle marker is keyed on the listing options too (`--no-file-versions`, `--ignore-zeros`, `--gnu-incremental`, `--detect-gnu-incremental`, `--encoding`), so a check made under one view is never reused under another; reopening an existing overlay always compares the base with the recorded identity, and `--base-digest` (including `none`) applies only at creation; the `RATARMOUNT_TEST_HASH_*` seams exist only in test builds (release binaries contain no `RATARMOUNT_TEST_` string); `sandbox run` checks the control-socket length after resolving `TMPDIR` (a short symlink to a long directory now takes the short-base fallback); the layer cache also sweeps old `.copy-XXXXXX.tar.zst` leftovers (exact shape, cache only); a read-only `--lower` mount refused because an existing `--journal` file lies inside the base names that file and `--force-stack-mismatch`.

- **Digest states:** `overlay info`, the root xattr `user.ratarmount.base_digest_state`, `diff --hash --json` and the `sandbox run` `patch_hash` report carry a stable `base_digest_state` of `present`, `pending` or `none` (see docs/sandbox.md, "Digest states"); `base_pending` stays for compatibility. A digest resolved by `overlay seal` is written back to a writable index cache (and to the overlay database only otherwise); concurrent seals over a read-only archive hash once per seal, and `overlay verify` always rehashes the base. (#133)

- Git mounts (`git:///…`, `--git`) show writable-style modes `0644`/`0755`/`0777` instead of read-only modes. (#133)
- `ratarmount diff` takes `BASE` as a positional argument (it no longer reads only `meta.base_url`) and reports a rename as a delete plus an add; the old rename detection is behind `--detect-renames`. (#133)
- A `-w` overlay created by this version records the base's size and mtime and refuses to open after an external change to either; pass `--force-base-mismatch` to override. (#133)
- **Weak base identity for directories:** a new `-w`, `--overlay-tmpfs` or `--sandbox` overlay over a **directory** base no longer reads the base's content: its digest is `weak:<hex>` over a sorted (path, type, size, mtime; symlink target) manifest from an `lstat` walk, so a 1 GiB directory base mounts in tens of milliseconds (release build; a debug build took 65-86 s before) and FIFOs or unreadable files in the base no longer break creation. An overlay inside a directory base is excluded from the digest (recorded, append-only, in `base_weak_excludes`), ratarmount index sidecars (`.index.sqlite`, `.rgzi`, `.gzidx`, commit journals) are ignored, `--base-digest` is also accepted with `--lower`, and `sandbox run` takes `--base-digest`. A strong digest is available on request: `ratarmount overlay digest-base DIR` (or `ratarmount snapshot`) prints `sha256:<hex>`, which `--base-digest` records. Git bases (tree sha) are unchanged. A weak digest cannot see a content edit that keeps size and mtime. (#133)
- **Archive bases are hashed after the mount is serving:** an archive base whose SHA-256 is not yet cached is recorded as `pending` and hashed on a background thread; the digest, its cache entry and `stack_digest` are filled in when it finishes. Until then `overlay info` prints `base_digest: pending (computing)` and the root xattrs `user.ratarmount.base_digest` and `stack_digest` are empty. `overlay seal`, `verify`, `pack`, `diff --hash` and `sandbox run` resolve a `pending` digest themselves (one cached pass over the archive); `--base-digest` skips all hashing. An archive's digest is computed once and cached in its index: concurrent first mounts hash it once (per-archive lock), later mounts read the cache, and without a writable index cache the digest stays `pending` instead of being rehashed on every mount. (#133)
- **Behaviour change for working-tree (live directory) bases:** an overlay on a directory base now refuses to reopen after the base's entries, sizes or mtimes change (`base mismatch … use --force-base-mismatch to override`); earlier builds never checked directory bases on remount. Index sidecars written into the base are ignored. A repack that writes into the base (for example `--repack-seekable` next to its input) is base content and changes the digest. `overlay verify` also compares the base (weak manifest, or the full digest when a strong one is recorded). (#133)
- `--lower BUNDLE` cache entries are keyed by the SHA-256 of the bundle file (`layers/<sha256>`) instead of the claimed layer digest; a fill (or a marker miss) verifies the bundle against the mounted base and lowers by reading the paths the layer mentions (not the whole base); `.verified` markers are used only when the whole stack below is sealed and the base has a strong digest (a supplied `--base-digest` or a cached archive digest); weak directory bases always re-verify; entries from earlier builds are ignored. (#133)
- Names that are not UTF-8 get `EILSEQ` through the write overlay and FUSE instead of being lossy-converted. (#133)
- `sandbox run` containers get `--cap-drop ALL`, `--security-opt no-new-privileges` and `--pids-limit 4096`; use `--cap-add` and `--pids-limit` to adjust. (#133)
- `sandbox run` mounts with `--control-socket-only` and reads its counters over a private socket: the in-FS `/.ratarmount-control/` (host pid, memory stats, `unmount`) is no longer visible inside the container or the graded mount. (#133)
- Experimental, may change: `overlay digest-base` and its `--exclude-overlay`, `overlay unpack --max-bytes/--max-entries` and `RATARMOUNT_BUNDLE_MAX_BYTES`/`RATARMOUNT_BUNDLE_MAX_ENTRIES`, `overlay verify --no-base-check`, `sandbox run --cap-add/--pids-limit/--base-digest`, `--control-socket-only`. (#133)
- `overlay unpack` without a reachable recorded stack now says `content not verified; run overlay verify DIR BASE before using it as a lower` (exit 0 unchanged). (#133)
- A `--lower` bundle verification marker is used only when the mount serves the archive's own paths: `--prefix`, `--transform`, recursion, `--bind`, corpus and rolling series always re-verify. (#133)
- A `--journal` file that already exists inside a directory base is base content for the `--lower` base check with `-w` too; only new paths and paths already in a recorded excluded set are excluded (a FUSE mount point inside a directory base is refused at startup with exit 2). A read-only `--lower` mount with an existing journal inside the base is refused on the next mount; keep the journal outside the base. (#133)
- `sandbox run` redacts signed URLs in the error it exits with, including a failure while finishing; URL redaction no longer panics on multibyte text. (#133)

### Features

- Sandbox and grading: sealed layers and `--lower` stacks, `overlay` verbs (`import`, `import-upperdir`, `seal`, `verify`, `fsck`, `pack`, `unpack`, `info`, `digest-base`), bundles as `.tar.zst`, `sandbox run`, the operation journal, canonical diff hashing. (#133)

### Fixes

- A `--lower` bundle is verified against the mounted base and lowers before it is cached, and a cached layer is re-verified on reuse for a new base/stack view. (#133)
- A `--lower` stack refuses a bottom lower sealed against a different base (override: `--force-stack-mismatch`) and reports the mounted base's identity, not the lower's record. (#133)
- Overlay metadata, bundles, `overlay info`, `sandbox run` output and mount progress lines no longer show credentials from remote base URLs (userinfo and query are removed for remote schemes; local paths and `git:///` URLs are untouched). (#133)
- `overlay pack` redacts credentials from `meta.json` and the packed DB. (#133)
- `overlay verify` also checks the base against the recorded digest (strong digests are rehashed, so same-size mtime-restored edits are caught; weak directory digests are re-walked) and exits 1 with `base mismatch`; `--no-base-check` skips it. (#133)
- Re-running `overlay seal` completes an interrupted seal (sentinel and read-only modes). (#133)
- A killed `overlay import` is marked incomplete (`overlay fsck` reports it, `seal` refuses); `overlay unpack` and `--lower` staging directories stay writable until publication, are held by a lock while active, and stale ones are swept. (#133)
- `/.ratarmount-control/` is reserved in a `-w` overlay when `--control-interface` is on, and `overlay import` refuses it. (#133)
- The control socket `ratarmount-control-<pid>.sock` is removed on unmount, including an external `fusermount -u`; `sandbox run` gives its mount child a private `TMPDIR` and removes the whole private run directory (socket included) on cleanup. (#133)
- `overlay unpack` caps extracted bytes and entries; overlay metadata newer than this build, and bundles with a newer layout, are refused. (#133)
- `sandbox run` mounts under a private 0700 directory. (#133)
- Gate-1 review fixes: a mount's digest-cache peek never waits for another mount's hash (the second mount serves at once); `--lower` bundle verification markers are keyed only by a computed single-archive digest (not by a union's first input or a supplied claim); `diff --hash --json` and the `sandbox run` report give `base`/`stack` as `null` (`base_pending: true`) while the base digest is pending; `overlay verify` follows a symlink to the base; a read-only `--lower` mount no longer excludes an invocation path that already exists in the base; `overlay unpack` caps decoded bytes while streaming (and `meta.json` at 1 MiB) and sweeps only its own staging (`.ratarmount-copy-*` in the layer cache, never the destination's parent); `sandbox run` error text redacts every URL, including ones a library rewrote (`webdav://` to `http://`); an archive named like `x.index.sqlite.tar` no longer defeats the index-sidecar exclusion. (#133)
- Overlay databases are opened through checked SQLite opens: the descriptor SQLite actually opened is checked, so a name swapped to another file and back during the open is refused. Linux and macOS (64-bit glibc / Darwin) install the checks at load time or, in the Python wheel, before the module is published; Windows checks only the path's type; other Unix ABIs refuse every overlay-database open. See docs/sandbox.md, "Checked overlay-database opens by platform". A daemonized mount (no `-f`) still holds no kernel lock on its overlay database after it forks (#183). (#151)
- `overlay seal`, `unseal` and `overlay unpack` change file modes without opening the files, `overlay pack` ships SQLite copies of the layer database and of the `--include-index` index, and a failed first `-w` open no longer truncates an existing 0-byte database itself: none of them can release another connection's SQLite locks in the same process any more. `--include-index` now fails the pack for an index it cannot copy through SQLite alone (a rollback `-journal`, a `-wal` without `-shm`, a symlink, an unreadable or substituted file) instead of shipping it raw, and a failed first open removes the new database only while its name still holds the file SQLite opened. That check proves the name holds the file SQLite opened, not that this open created it: when two processes race the first `-w` open of the same empty folder, the one whose initialization fails can still remove the other's new database (a removal, not a close, so no lock is released). (#149, #156, #160)
- A panic inside a host `stat` call (for example rustix 1.1 on a pre-epoch mtime on macOS) in `overlay fsck`, `seal`, `verify`, `pack` and `diff` is now an error naming the path (exit 2) instead of aborting the verb with status 101. (#133)

## 0.1.35

### Changes

- BitTorrent (`bittorrent` feature, built into the deb, rpm, and portable packages and the macOS tarballs): `--torrent-swarm` now defaults to `never`, so a mount reads only from the cache, `xs=` metainfo and web seeds and never contacts public trackers, DHT or LAN peer discovery unless asked. A magnet with no cached metadata and no `xs=` source, or a piece no web seed can serve, now fails with an error that says to pass `--torrent-swarm lan or auto`; pass `--torrent-swarm auto` for the old behaviour. `--seed` now needs an explicit `--torrent-swarm lan`, `auto` or `always`. (#110)
- FUSE `-w`: a file that is unlinked or replaced while the kernel still holds it keeps returning its old bytes and attributes (`nlink` 0) until the last reference is dropped. A write handle opened before that keeps writing the orphan (discarded at commit). A new write open or an fh-less setattr on that nodeid returns `EACCES`. (#104, fixes #88)
- FUSE now returns the real errno (ENOTDIR, EISDIR, EXDEV, ELOOP, ENOTEMPTY, ENOSPC, EMFILE, ENFILE, …) instead of EIO for unmapped I/O errors. (#103)
- FUSE foreground (`-f`): an `ECONNABORTED` from the session read at unmount is now a clean exit (exit 0), like `ENODEV`, and is logged at info; it used to exit 1 when `FORGET`s raced the unmount. (#104, #105)
- FUSE `-w` copy-on-write no longer publishes a short file. The copy is written to a `.ratarmount.overlay.cow-*` temp, `fsync`'d, then renamed. A short read, or a source whose length changed during the copy, fails the copy; FUSE returns `EIO` and the temp is removed. A crash mid-copy leaves the temp, which list, lookup, and `--commit-overlay` ignore. The next open removes leftover temps it can reach; a directory that cannot be read is logged and skipped and does not fail the open. A second open of the same overlay database is refused while the first holds it, so it cannot delete an in-progress temp. An archive member whose name starts with `.ratarmount.overlay.cow-` (ASCII case ignored) is hidden from the mount. `--commit-overlay` drops only tombstoned or overlay-replaced paths. A cow-prefixed archive member is neither, so it stays in the archive unchanged. (#129, fixes #126)
- ISO indexes are `rock-ridge-joliet-v4`. An older sidecar (`rock-ridge-joliet-v1` through `v3`, or any other `isoMetadataVersion`) is rebuilt on open. (#127, #123)
- `--passthrough` defaults to `auto` (Linux ≥ 6.9, ABI ≥ 7.40): passthrough is used only for a read-only mount when the process has `CAP_SYS_ADMIN` in the initial user namespace and the source is a write overlay or exposes backing extents; otherwise reads stay in the daemon. `--passthrough on` errors if the kernel has no `FUSE_PASSTHROUGH`. `--direct-io` disables passthrough. Member copy stays off unless `--passthrough-copy` and a non-zero `--passthrough-copy-max`. (#110)
- Mounts are `exec` by default. With the default owner-only access and `auto_unmount`, the kernel mount gets `allow_other`, but ratarmount still answers only the mounting user unless `-o allow_other` or `allow_root` is given. (#110)
- `export-parquet` is a default feature of the `ratarmount` binary. `bittorrent` is not a default Cargo feature; the deb, rpm, and portable packages and the macOS tarballs enable it. (#110)

### Features

- `hf://` reads a commit-pinned Hugging Face repo; `--publish-index` can upload the sidecar to the Hub, S3, GCS, or Azure; `-w` can commit the archive back to the Hub as one commit. Cached Hub snapshots can be shared with `huggingface_hub` and mounted offline. (#110)
- Mount a `.torrent` or magnet. With the default `--torrent-swarm never`, bytes come from the cache, `xs=` metainfo, and web seeds. `lan`, `auto`, and `always` are opt-in. `--seed` uploads only with one of those policies. (#110)
- Agent sandboxes: `--sandbox`, read-only overlay globs, byte and file quotas, `overlay-stats`, a sandbox daemon (`sandbox` / `new` / `list` / `destroy`), and a RAM overlay. Owner, group, and umask can be mapped. `ratarmount diff` writes a patch of the overlay against the base. (#110)
- Python package `ratarmount-rs` (PyO3/maturin) over the session API, plus fsspec, torch, and WebDataset extras, `mount()`, and index publish. Its version comes from the workspace Cargo version (maturin `dynamic` version; no separate pin). (#110)
- Safetensors and GGUF mount as a tree of tensor files (raw bytes, plus JSON sidecars). Parent directories of tensor names are listed. Nested checkpoints open without a temp spool. (#110)
- Git: `--git`, `--git-ref`, `repo@REV`, `--git-prefix`. A bad explicit ref errors instead of falling back to HEAD. `--git-synthetic-head` adds a history-free `.git` so `git status` / `diff` work. `--bind` mounts a source at a subpath; a corpus list mounts many repos as one tree. (#110)
- `ratarmount shard` and `ratarmount export-index` for dataset shards. `ratarmount snapshot` wraps restic. `--roll-every` rolls a write-mounted archive by size or time. `--memory-budget` caps buffers, decode windows, and caches. User xattrs survive the write overlay and commit manifests. (#110)
- Docker/Podman volume plugin and a Kubernetes CSI node driver mount volumes with ratarmount. Their sockets are created mode 0600. (#110)
- HTTP(S) keeps a process-wide connection pool, Bearer auth, a redirect cache that does not send credentials to the redirect host, and a bounded parallel range prefetch. (#110)
- Seekable zstd can decode ahead. (#110)
- `--direct-io` sets `FOPEN_DIRECT_IO` on archive members (overlay files keep normal caching), forces passthrough off, and requests `FUSE_DIRECT_IO_ALLOW_MMAP` when the kernel offers it. It turns kernel readahead off. (#110)
- Linux kernels that advertise `FUSE_MAX_PAGES` (4.20+) get a 256-page request ceiling (1 MiB with 4 KiB pages); older Linux kernels, FreeBSD and other non-macOS targets stay at 32 pages; macOS keeps fuser's defaults. This is independent of `--direct-io`, and direct I/O does not turn a 128 KiB `cat` into a 1 MiB read. (#110)

### Fixes

- Joliet fallback no longer binds a Rock Ridge symlink-target directory (an `SL` directory) to a Joliet directory through a child match, and a run of those directories under a plain parent is one hop. Those bugs dropped or misplaced the directory's children. File type comes from the ISO directory flag; Rock Ridge `PX` supplies permission bits only, so a file is no longer shown as a directory. Devices, FIFOs, and sockets are regular files. (#127, #123, #119)
- FUSE `-w` implements `rename`, including rename over another name, without unlinking the target first. A cached destination name is not `INVAL_ENTRY`'d. Attribute cache on `-w` tracks what the kernel was told. (#87, #103, #91, #92, #84, fixes #86, #88)
- The overlay database is not recreated when it cannot be read or is missing its marker (unlinked members would reappear). The open error names the database path. A locked database says it is in use. `.ratarmount.overlay.sqlite*` and both marker names are hidden and not mutable through the mount. (#89, #94, #97, #99)
- Concurrent readers of one TAR or ZIP no longer share a file cursor (a read could return another member's bytes). ZIP Stored and zip-crate path opens are positional. Interrupted Windows range reads are retried. ZIP DOS timestamps are converted in Rust, so the zip and tar crates pass `cargo check` on the Windows CI job. That job does not run the servers or mount anything. (#111, #112, #121, #128)
- ZIP DOS timestamps: an invalid DOS date or a time in a spring-forward DST gap now gives mtime 0 instead of the current time or a normalized time, and a time in an autumn fold may differ by the zone's DST offset (usually an hour). (#128)
- VHDX images whose metadata items are packed at small offsets inside the metadata region (as qemu-img 11 writes them) now open; they were rejected because every item had to be 64 KiB aligned. The File Parameters and Logical Sector Size GUIDs were wrong and now follow MS-VHDX, and a logical sector size other than 512 or 4096 is rejected. (#108, #113)
- 9P and SMB clear `O_NONBLOCK` inherited from the listening socket (macOS/BSD was cutting large replies short). Accept treats `WouldBlock` and `Interrupted` as a poll, not a fatal error. (#114, #125)
- A closed stdout or stderr pipe after startup no longer panics the process (exit 101). This covers index status lines, the `ratarmount` binary, overlay commit and create-if-missing lines, and format-crate progress. (#95, #98, #100, #106, fixes #93, #102)
- `chmod` and timestamp updates on `-w` apply to the overlay file, so a program created in the overlay can be executed. (#110)
- Remote folder mounts use a published sibling index instead of scanning every nested archive. Remote TAR indexing coalesces member-header reads. A bzip2 block boundary no longer truncates a TAR listing. (#110)
- Docs and `hf://` examples use the Hugging Face owner `RealMattBrewer`. (#122)
- README, format, and benchmark guides were rewritten around local-model workflows. (#116)

### Packaging and build

- Workspace MSRV is Rust 1.90. CI has an `msrv` job. The crates.io dry-run reads `rust-version` from `Cargo.toml`. (#85, #109, #113)
- The portable glibc 2.31 tarball vendors OpenSSL statically. Releases through 0.1.34 linked bullseye `libssl.so.1.1` and failed to start on Arch, Ubuntu 22.04+, and current Fedora. Host `libarchive` and `libfuse3` are still dynamic. A shipped tarball gets OpenSSL fixes only when that tarball is rebuilt. (#107)

### Known issues

- Deb, rpm, and portable packages and the macOS tarballs enable `bittorrent` (vendored librqbit) and do not ship third-party license notices. The macOS staging copy of `LICENSE` is the project license only. (#110)
- Reported on [#110](https://github.com/hilather/ratarmount-rs/pull/110#issuecomment-6236724875):
  - `--commit-overlay` and live/interval/rolling commits can leave the archive mode 0600 (pre-existing; #110 added more commit paths that do this).
  - A `SIGKILL` during write churn can leave the mount hung until `echo 1 > /sys/fs/fuse/connections/<n>/abort` (pre-existing).
  - After a `kill -9` during live `.tar.zst` interval commits, an immediate `-w` remount can return intermittent `EIO` for files committed in the killed session; the archive is intact (seen on 0.1.34 too).
