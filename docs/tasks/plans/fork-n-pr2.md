## v1 limits

Exit 2. No session starts, except the cleanup limit tearing down a session this process already mounted.

### Hardlinks

Walk each top with `lstat` only. Do not follow symlinks. Recurse into subdirectories, including a nested mount. A symlink is not a regular file, whatever its target's `nlink` is. A directory is not a regular file, even when `st_nlink > 1`. A regular file with `nlink > 1` refuses. The error names the path.

Check in step 3, before any top database write and before fork. Recheck after the daemon child holds every top lock, before `Ready` and before any session. Foreground repeats that recheck after its locks, before serving. The recheck refusal unmounts nothing this process did not mount.

The step-4 hold is not the after-handoff proof. A second parent walk immediately after that hold is not the recheck. The recheck hold is `RATARMOUNT_TEST_FORK_N_HOLD_AFTER_LOCKS`, placed after `reacquire_exclusive` (daemon child) or after `open` has taken the locks (foreground), and before the recheck, `Ready`, and any `Session::new`. While that hold is blocked, another process's `BEGIN IMMEDIATE` fails on every top database, and the serving process has written `locks-held` to the path in `RATARMOUNT_TEST_FORK_N_LOCK_MARKER`. The test creates the extra link during this hold, then releases. The process that then exits 2 is the one that wrote the marker. For the daemon that pid is not the launcher pid. No `Ready` byte is sent. The tests spawn the `ratarmount` binary. They do not call the walk function. Both holds are compiled out of release builds the same way as the other `RATARMOUNT_TEST_*` holds. The positive file is the nested fixture `top/sub/dir/file`, not an immediate child of the top. `fork_n_hardlink_nlink_at_start` and both after-handoff tests use that same nested path. The symlink-to-directory control points at a directory outside the top.

### Self-reopen

`ForkNStorage::admit(path, kind)` runs before a dependency is opened or adopted.

- Canonicalize the path. If the final component does not exist, canonicalize the existing ancestor and apply the same containment checks to that ancestor plus the lexical remainder. Containment is still a refusal, and the file is not created. A symlink loop, a missing ancestor, or any other canonicalize error is a refusal, not a warning.
- Refuse when the resolved path is equal to or under any cohort mountpoint, including a backing file that is outside every top.
- Refuse when a source or shared dependency is equal to or under any top.
- Before SQLite open, admit the database path and its `-wal`, `-shm`, and `-journal` companions. Refuse when one of those canonicalizes under a mountpoint or under a **different** top. The database this top creates inside that same top, and its companions beside it, are that top, not a hit. A `-wal` symlink into a mountpoint is a hit even when the database file stays in the owning top.
- Where the caller is about to `File::open`, `admit` opens and returns the `File`. The caller reads that fd and does not `File::open` the path again. Holding the fd does not skip canonicalize. QCOW2 `open_backing` (`disk.rs:561`) still returns at `path.is_file()` (`:573`) when the backing file is missing; that return is not the absent-component proof, and `admit` is not called on it. When `is_file()` is true, `admit` runs before `File::open` at `:579` and `open_backing` adopts the returned `File`.
- The absent-final-component subcase is an index or sidecar destination the opener would create or truncate. It does not use `open_backing`. Containment of the existing ancestor plus the lexical remainder is still a refusal, and the destination is not created. The test asserts a create/truncate spy count of 0 and that the path is absent after the refusal.
- The same guard covers VMDK extent opens, TAR index and sidecar opens, split-volume paths, index-folder destinations, SQLite companion/temp/publication paths, materialized bodies, seek-index sidecars, bundle-cache paths, and enabled range-cache artifacts. A fallback and an optional-cache error handler must not swallow the refusal. The `fork_n_storage_` row asserts both.
- An uninstalled slot does not change legacy opens. A direct `ForkNStorage::admit` call is not the named regression; that test drives QCOW2 `open_backing` through the Fork-N factory path.

### Cleanup

Before a session, refuse a target that mountinfo already lists as a mountpoint, and a target that is not an empty directory. A directory this process just created is empty and is eligible.

The child records `(st_dev, st_ino)` and the mount id after that session's mount succeeds, and reports the triple to the launcher. Failed-startup cleanup unmounts a path only when the child reported that triple and `stat` still shows the same `(st_dev, st_ino)`. The unmount is `fusermount -u` with no `-z` and is not `unmount_lazy`. No report, or a changed inode, means leave it mounted. The launcher does not unmount a cohort path by name alone: the session lives in the child, and an unrelated mount at that path stays up. A killed child is the same rule: the launcher unmounts only triples already reported, then reaps. The serving SIGTERM busy-then-lazy policy is unchanged and is not used on this failure path.

`fork_n_cleanup_occupied_target` and `fork_n_cleanup_partial_start` spawn the Fork-N binary. A helper the binary does not call is not the proof. Occupied and non-empty targets exit 2 before any session and do not unmount.

Partial start uses `RATARMOUNT_TEST_FORK_N_FAIL_MOUNT=B`. B's thread returns an error after A has reported `(st_dev, st_ino, mount_id)` and before B calls `Session::new`. When `RATARMOUNT_TEST_FUSERMOUNT` is set, cleanup runs that program instead of `fusermount`/`fusermount3` and passes the same argv. The recorder must see one call, `-u`, no `-z`, and path A only.

The stomp case sets `RATARMOUNT_TEST_FORK_N_HOLD_AFTER_REPORT=A` and keeps `RATARMOUNT_TEST_FORK_N_FAIL_MOUNT=B`, so B still fails and cleanup runs. While A is held, the test bind-mounts a fresh empty directory onto A. Cleanup re-stats, the inode no longer matches, and the recorder sees zero calls because the inode check suppressed the unmount. The test then unmounts its own bind. If the bind cannot be created, that subcase prints `skip:` and the non-stomp case still runs. A missing `/dev/fuse` skips the whole partial-start test with `skip:`; it does not pass.

The killed-child case SIGKILLs the child after A's report and keeps `FAIL_MOUNT=B`. The launcher's fallback unmount uses the inode rule on the reported triple. The recorder sees one `-u` of A and no `-z`. Launcher status is nonzero. A fresh process can open each top database (`BEGIN IMMEDIATE` succeeds). The parent does not keep a connection after the child is gone.

Foreground partial start (`-f`, no launcher and no fork) uses the same `FAIL_MOUNT=B`. A reports `(st_dev, st_ino, mount_id)`, B returns before `Session::new`, and the serving process unmounts A only when that recorded pair still matches and the mount is this process's owned FUSE session. The recorder sees one `-u` of A and no `-z`. Status is nonzero. B never gets a session. A fresh process can `BEGIN IMMEDIATE` on each top database.

- Worker-free permit: Preparing still closed, scoped tasks joined, no source pool initialized, no budget or transport mutex held by the calling thread, every registered parent SQLite connection closed. A live or unjoined pool refuses **without** forking and without taking that pool's lock.
- Source handoff admits disk read-only `SqliteIndex` only. In-memory, compact-shell, and SQLAR connections refuse daemon Fork-N before fork (exit 2, foreground guidance). Close the parent connection, drop its budget hook, reopen in the child, and refuse if the WAL-visible generation does not match the snapshot. One reopen shared by both tops.
- `reacquire_exclusive` opens a fresh connection, runs `PRAGMA LOCKING_MODE = EXCLUSIVE` (the statement at `write_overlay.rs:1204`), then `BEGIN EXCLUSIVE; COMMIT;` (the statement at `:1287`, not the comments at `:1281`–`:1286`), and re-reads seal, stack, and tombstones. The commit does not keep the lock unless the pragma ran. Then rebuild `OverlayQuota` from a scan of the locked directory and install that instance. Then the hardlink recheck. Then sessions. Any failure sends no `Ready`, starts no session, and drops child locks.
- Foreground does not fork and does not close or reopen. It keeps the quotas installed at `open` (no second scan) and runs the same hardlink recheck.
- N threads in the serving process each call the existing blocking FUSE mount, so one process holds N `fuser::Session` values. The coordinator joins them. A worker does not call `finish_overlay_serve` (that sets process-global shutdown) and does not `process::exit` the cohort. External unmount of one top ends that worker; siblings stay writable.
- `ForkNSignalState` is two atomic counters. Each watcher and the coordinator keep their own cursors, so a later INT does not erase a pending TERM. TERM keeps busy-then-lazy on every still-serving path. The lifecycle test makes the non-lazy unmount return busy before INT-then-TERM goes lazy on every still-serving path. INT-only stays retry-only and never calls `unmount_lazy`. `spawn_signal_fuse_unmount_for_session` checks its session token every iteration, including after a signal was already seen, so a watcher joins when `seen > 0`.
- Launcher records SIGINT and SIGTERM before fork, closes its unused channel end, forwards the signal to the child pid (not via the process group), and treats cancellation as sticky against a queued `Ready`. Channel EOF before `Accept` cancels. One cohort deadline; `wait_until_mounted` alone is not the wait. After A is ready while B is held, the launcher forwards the signal and releases B. The child owns the FUSE session: it unmounts A under the recorded `(st_dev, st_ino)` plus that owned session, and B never starts or is promptly unmounted. The launcher does not fusermount A while the child is alive. If the child is already dead, the launcher's fallback unmounts only reported triples whose inode still matches. Launcher status on that path is nonzero. After `Ready`/`Accept` the launcher exits and the daemon stays up. Timeout, partial ready, and an unexpected child exit use the cleanup limit and the launcher reaps. A duplicated channel fd is not left open.
- Pending archive digest: one cohort worker hashes the shared base once and writes the result through `Weak` into every still-pending top. Do not loop the one-target helper in `base_digest.rs`. A top with no writable index stays pending. Join the worker once at shutdown.
- Each top receives the process-wide encoding, read-only/allow policy, quota, and commit-mode/manifest settings a single overlay gets today. Counters stay per top. There is no per-top flag syntax. Quota handoff test shape: parent scan sees A at 10 bytes under a 100-byte limit; a writer grows that dirty file to 90 and exits; the child, holding every lock, rescans; usage is 90; 20 more bytes are denied; 10 are allowed; B's counters stay put. File-count refresh is a second case. A quota failure on A does not move B's counters. Direct-I/O, readahead, and passthrough from the process-wide flags reach every session.

Constructor admission is a closed table, default refuse, checked before the constructor runs. Admitted here, each with a guard at every path it opens: local folder (register the root once, not each member), TAR and its index plus WAL/SHM/journal companions, QCOW2 and its backing chain, VMDK extents, factory split-volume paths, `--index-file` and `--index-folders` destinations, SQLite temp and publication paths, materialized bodies, seek-index sidecars, bundle-cache paths, enabled range-cache artifacts, and direct HTTP range plus zstd as the deferred daemon pair. Torrent, SSH ProxyJump, Hub-cache publication, and rapidgzip are not admitted. Foreground Fork-N refuses each of them with the coverage diagnostic before the constructor. Daemon torrent sources fail the earlier torrent ban (`use --foreground`) and never reach the coverage check. Daemon SSH ProxyJump, Hub-cache publication, and rapidgzip fail before the constructor with the coverage diagnostic and `use --foreground`. A daemon torrent test that only sees the coverage diagnostic does not pass `fork_n_daemon_sources_`. A changed input, an override, a bind, and a nested open use the same table. A lazy nested unsafe backing or index after startup fails that operation and leaves the other mounts up. Do not silently switch backends.

Inside-base tops stay visible through the folder source. No source filter is added. Frozen excludes still drop the saved subtree from the weak digest.
