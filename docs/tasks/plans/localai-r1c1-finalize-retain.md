## 1. Goal

1. One `finalize_top`, shared by `sandbox run` and the supervisor, with `sandbox run`'s reports byte-identical and its error order (classify, gate, compose) kept.
2. A v2 `finalize {id, pack, request_id}` that stops an attempt with the non-forcing unmount helper (no lazy unmount, no force flag; ruling 7), then fscks, seals under the top's overlay root flock with a deadline, hashes, optionally packs and reports. It answers `writers_active` while writers remain, a busy mount (`EBUSY`) included, and is retry-safe under R1a's `request_id` (Keystone #6): a retry acts only on the attempt its record names, by ID and instance, and answers `not_found` once that attempt is gone (ruling 5).
3. `new` with `retain: true` and a commit of the finalized attempt into `state/retained/ID`: durable before it is acknowledged, never deleted by a restart, usable within the run as a lower, and recorded with the identity R1c-2 needs (§5.7).
4. Durability owned by retain and finalize (ruling 1+2): every finalize, with or without `retain`, syncs the files and directories of every layer the attempt references, bundle cache entries included, after their publication completed; cache extraction never syncs. Every node is opened without following symlinks and checked, on the descriptor it syncs, against its tree's filesystem, and each lower's identity is checked again under its entry lock (ruling 6).
5. Linux only (ruling 7): on any other platform finalize and `retain` answer `invalid_request` before anything stops or starts; v1 is unchanged everywhere.

**Applied as written** (sweep 1, Codex B3; run 2 sweep 1 Claude N5): "every retain and every finalize" is every try of every finalize, with or without `retain`, the fast path for an attempt already finalized or retained included: it runs S again before it returns the stored report. Only R1a's replay of a `done` record returns its stored answer without running anything, as R1a's contract requires (§5.6).
**Boundaries stated for Keystone's attention:**
- **The base** (sweep 1, Claude N6; wording corrected in sweep 2, Codex N3). Ruling 1+2 enumerates layers ("the layer files, then the destination directory, then its parent"). The base is not a layer: it is the registered source ratarmount never writes, prepared in place at `create_base`. It is not synced, and keeping it durable is the caller's job: the gates compare metadata only (stamps, weak manifests, tree ids; `overlay_meta.rs:1790-1795`), and a weak manifest is blind to a same-size change with a restored mtime (`:1629-1631`), so a lost base write with surviving metadata need not be refused (Risk 3).
- **`sandbox run`** (sweep 2, Claude N5). "Finalize" in the ruling is the supervisor's `finalize` operation, the one R1c defines (source doc `:111-120`). `sandbox run` shares `finalize_top` because the source doc factors it out of `sandbox run` (`:111`), but it is not that operation and retains nothing, and source test 10 holds its reports and behaviour unchanged, so S is not added to it. If Keystone wants `sandbox run` synced too, it is the same S over its top and lowers.
- **R1a's retry window** (ruling 5; approval note (a)). R1a evicts the oldest records other than `running` ones past 65,536 records or 64 MiB (`requests.rs:932-937` at `cf8f626`), and "an evicted ID that is retried runs as a new request" (`docs/sandbox.md:2440-2442`). Approval note (a) closes ruling 5's scenario for finalize records: a finalize record is never evicted while its target attempt exists (§5.2 Pins), and when the caps cannot be met without evicting one, a new request is refused with `capacity` and nothing is written (fail closed). A finalize record becomes evictable only once its attempt is gone (destroyed, or discarded by a restart), so a retry evicted after that runs as a new request, which can reach a new attempt of the same name only after the old one was destroyed and its ID drawn again (Risk 11).
- **Filesystems S trusts** (ruling 6; run 2 sweep 1 Codex B1). Comparing every file's device with its tree's refuses a tree on an overlayfs whose layers lie on different filesystems: there non-directories report the real file's device while directories report the overlay's (kernel documentation, "Overlay objects"). Uniform devices are not enough either: overlayfs's `fsync` does not sync a file that exists only in a lower layer, and does nothing on a `volatile` mount (row 30). S therefore syncs only on filesystems whose fsync reaches their storage (ext2/3/4, xfs, btrfs) and tmpfs (no storage to lose), and refuses every other type, overlayfs and FUSE included. Read-only images (squashfs, erofs, iso9660) are refused as well: having no dirty data of their own says nothing about the image file behind them, which a loop device reads through the page cache and nothing in S syncs (`drivers/block/loop.c`; run 2 sweep 4 Codex B2). A shared device does not imply a shared filesystem (an overlayfs file bind-mounted into a tree reports the lower's real device; run 2 sweep 3 Codex B1), so S checks every descriptor's own `fstatfs`, files included. Every directory S syncs lies in a tree, is a tree's parent, or sits above that parent on the parent's filesystem, and every file lies in a tree on its root's filesystem unless something is mounted inside the tree; so the preflight before the stop (and at `new` with `retain`) checks each tree root and its parent, the readability of each chain, and that nothing is mounted inside a tree (§5.5; run 2 sweeps 2 and 3, Claude B1 and N4). Inside a container, the state directory, the bundle cache and every lower belong on a volume mounted at or above the directory that holds them (Risk 12).

## 2. Scope

- `protocol.rs`: `retain` on v2 `new`; v2 `finalize`; `all` on v2 `list`; codes `writers_active` and `retained`; statuses `finalizing`, `finalized`, `retained`.
- `requests.rs`: finalize records in line schema `v: 2`, carrying their `target` in every state (ruling 5).

- `overlay_pack.rs`: `remove_tree`; `sync_tree`, the descriptor walk of ruling 6; `rename_no_replace` across two directories; the layer entry lock in `publish_layer`, in a cache hit (with the publication check) and for S.

- `ratarmount-compositing`: `SealOperation::acquire_until` and its stub twin.
- CLI, Python client, docs, CHANGELOG, `AGENTS.md` rows, manifest re-reviews.

## 5. Design

### 5.1 Protocol

- **v2 `new`** gains `retain: bool` (`#[serde(default, skip_serializing_if = "is_false")]`). R1a's `defaults()` (`requests.rs:335-346`, with R1b's `lowers`) gains `("retain", false)`, so R1a's golden digest (U5) is unchanged. R1b's routing rule becomes: a v2 `new` without `request_id`, `lowers`, `journal` or `retain` has the v1 form.
- **v2 `finalize {id, pack = false, request_id?}`**, `deny_unknown_fields` through the enum; `request_id` uses R1b's string-only `some` deserializer (`null` refused). `defaults()` gains `("pack", false)` for `finalize`; `id` is hashed.
- **v1** is untouched: `finalize` and `retain` stay `invalid_request` (R1a U1).
- **v2 `list`** gains `all: bool` (`#[serde(default, skip_serializing_if = "is_false")]`; run 1 skeptic sweep 6 N2): without it, v2 `list` answers exactly what v1 `list` answers, so R1a's U2 equality holds in every state; `all: true` appends the retained entries of this run (§5.7), each with the v1 attempt shape. v1 `list` keeps its code over the attempts map.
- **Platform** (ruling 7): on any platform other than Linux, v2 `finalize` and v2 `new` with `retain: true` answer `invalid_request` (§5.5); everything else is unchanged there.
- **New codes:** `writers_active` (v2 `finalize` only) and `retained` (`destroy {id}` of a retained ID, v1 and v2 alike, reachable only after a v2 client retained). Existing codes keep their meaning: `lower_changed` (R1b) for a changed recorded lower, `in_use` for a busy lower, `capacity`, `io`.
- **Statuses:** `finalizing` (finalize started and has not finished; resumable) and `finalized` live in the attempts map and are visible in v1 `list` once a v2 client finalizes; `retained` appears only in v2 `list`.

### 5.2 One durable-log engine (the requirement, and its premise)

**Premise.** The request names "the ONE shared fsync/compaction helper used by requests.jsonl (R1a) and the R1b journal". Only R1a has one; R1b's journal is the child-written `OpLog` file (row 7). R1c-1 leaves `OpLog` alone and makes the journal durable at retain, like every other file the retained attempt references (§5.6).

**Extract, never copy.** Step 1 moves R1a's record-independent mechanics from `RequestLog` into `ratarmount/src/sandbox/state_log.rs` as `StateLog<R: Records>`: the checked open, the open-time file and directory syncs, the bounded streaming replay with torn-tail truncation and damage refusal, the leftover sweep, append-then-`sync_data` with truncation, `Broken`, verbatim compaction with backoff, fault points and events, and `sync_dir`. `Records` supplies parsing, applying, the live lines in file order, live bytes, the compaction precondition, the file's messages, and its fixed line bound, which replay uses for the torn tail and for skipping an over-long line (R1a's `LINE_BOUND`, about 4.5 MiB, for `requests.jsonl`, `requests.rs:42-50`, `:556`, `:572`; 64 KiB for `retained.jsonl`; run 2 sweep 2 Claude N4). `RequestLog` becomes `StateLog<RequestRecords>`; the record rules (eviction, reservation, `op_hash`) stay in `requests.rs`. Every name R1a's tests use stays (`faults`, `events`, `line_high_water`, `live_lines()`, `is_broken()`, `status()`, `descriptor()`, `TEST_FAULTS`, `TEST_LIMITS`, `BEFORE_OUTCOME`), messages keep their text, and each instance has its own fault queue and events, so R1a's suite and its event assertions (`requests_tests.rs:647`, `:780-790`) run unchanged. `retained.jsonl` is `StateLog<RetainedRecords>`. Every directory fsync outside the trees S walks (the logs' directory, the retained tree's parents, lower parents and every ancestor) goes through that `sync_dir`; the nodes inside a tree are synced on `overlay_pack::sync_tree`'s own descriptors, which ruling 6 requires (§5.6). No `syncfs`, and no second log engine or log fsync helper.

**Finalize request records** (ruling 5) live in `requests.jsonl` in **line schema version 2**, as R1a's plan prescribes for a change of members ("a later change to the line schema bumps `v`", `:159`): `v: 2`, `op: "finalize"`, and a `target` member `{"id": ID, "instance": INSTANCE}` in **every** state. Otherwise a `v: 2` line keeps R1a's members per state exactly (run 2 sweep 2 Claude N7): `running` and `retryable` carry none, `done` carries `attempts` and `result`, `failed` carries `attempts` and `error` (`requests.rs:249-254`); a finalize `done` line's `attempts` is `[target.id]` and a `failed` one's is `[]`, as `resolve_interrupted` writes it (`:833-841`), so the encoder and the parser share one table. `instance` is the random token the attempt got when `new` recorded it (§5.7), so a record names one attempt, not a name that can be drawn again. `new` records keep `v: 1` and R1a's members byte for byte, so R1a's records, its golden lines (U5) and its replay are untouched.
- **Parsing.** `parse_line` keeps R1a's order (the whole line must be JSON before its schema is judged) and keys on `v`: `v: 1` is R1a's member table and must be `op: "new"`; `v: 2` must be `op: "finalize"` with exactly the common members, `target` and R1a's members for its state, where `target.id` passes `validate_name`, `target.instance` is 32 lowercase hex digits, a `done` line's `attempts` is `[target.id]` and a `failed` line's is empty; anything else is a schema error that refuses the start. R1a's refused examples therefore stay refused unchanged: a `new` line with `v: 2` (`requests_tests.rs:695`) and a `v: 1` line with `op: "finalize"` (`:702`). An R1a or R1b daemon refuses every `v: 2` line at start, fail closed (R1a plan `:403`; Risk 9).
- **Compaction and reopen.** Compaction writes live lines verbatim and replay re-parses them, so `target` survives both. `Record` keeps its kind and target, so `resolve_interrupted` writes a `v: 2` `failed` line with the same target and the finalize message ("finalize was cut off by a supervisor restart before it finished; an attempt that was not retained was discarded, and a retained one is kept on disk"), and R1a's message for a `new` record.
- **Reservation.** R1a reserves the attempt IDs a stored answer names (`requests.rs:388-389`, `:917-919`). A finalize `done` record's report names its target, so its `attempts` member is `[target.id]` and the ID stays reserved while the record lives, as R1a's `done` lines reserve theirs. `running`, `retryable` and `failed` finalize records store no answer that names the attempt and reserve nothing: their target carries the instance, so the ID may be drawn again for a new attempt and no retry ever reaches that attempt (ruling 5's regression, T23). The docs' ID sentence is narrowed to stored answers (§5.12).
- **Code changes.** `Kind` gains `Finalize`; `LineOut`/`LineIn` gain `target`; `encode_line`, `done_line`, `begin` and `finish` take the kind and the target; `stored()` reads `result` or `error` as before. Every finalize error is `retryable` (nothing needs undoing; a retry resumes, §5.4). Only a restart writes `failed`. R1a's eviction applies to a finalize record only once its target attempt is gone (approval note (a); Pins below).
- **Pins** (Keystone approval note (a)). A finalize record is never evicted from the retry window while its target exists. `RequestRecords` keeps the pinned targets: `pin({id, instance})` when `new` records an attempt and `unpin` when `destroy` removes it; a commit into `retained/` keeps the pin, since the retained attempt is the same target. Eviction itself is R1a's rule, in the run and in replay alike (the oldest records other than the newest and other than `running` ones), so memory always equals a replay of the file; the run keeps a pinned record out of reach by appending its line again, byte for byte, before it writes a line that would evict it, which moves it to the end of the window (sweep 1 Codex B1: replay used to keep every finalize record while the run evicted unpinned ones, so a restart evicted a `new` record the run had kept). `Supervisor::open` calls `set_pins` after `reconcile` with the live `retained.jsonl` records (by ID and instance) and the bare names under `retained/` (by ID, any instance); it evicts nothing. `begin` and `begin_finalize` first `admit` the new line, counted at the per-record cap so its outcome line can always be made room for: if a pinned record exists and the caps cannot be met even after every evictable record were evicted, the request is refused with `capacity` (naming finalize records whose attempts still exist, or running requests, and the remedy: destroy those attempts) before anything is written; an outcome append is never refused. A retained attempt keeps its finalize records pinned until R1c-2's `forget`; documented.

**`retained.jsonl`** (0600, owned, one link, opened like `requests.jsonl`), one record per attempt ID:

```text
{"v":1,"id":"attempt-a1B2c3","instance":"…","t":"retained","base":"task","layer_digest":"sha256:…","sealed_at":"…","prefix":[{"path":"…","layer_digest":"sha256:…","sealed_at":"…"}],"over":["attempt-z9Y8x7"],"paths":{"overlay":"…/retained/attempt-a1B2c3/overlay","bundle":null},"report":{…}}
{"v":1,"id":"attempt-a1B2c3","t":"aborted"}
```

A record is live while its last line is `retained`; `aborted` ends it and compaction drops it. There is no eviction; `--max-retained` bounds the live set. The line bound is 64 KiB: a report of about 3 KiB, `over`, and up to 32 prefix records of about 150 bytes plus a path each, so 32 lowers fit with paths averaging up to about 1.8 KiB (run 2 sweep 3 Claude N7: 16 KiB refused ordinary deep stacks with paths of about 250 bytes). `--max-retained` is capped at 4,096, so the engine keeps at most 256 MiB of live lines, the same envelope as 16 KiB × 16,384, and about 20 MiB for typical lines of about 5 KiB. `new` with `retain` measures that line before any attempt exists (§5.5, sweep 1 Claude N5); the same check at the commit is only a backstop. Damage before the last line refuses the start with this log's own advice ("moving it aside keeps every `retained/` tree; the records restart recovery reads are lost").

### 5.3 `finalize_top` (new `ratarmount/src/sandbox/finalize.rs`)

One function, called by `sandbox run`'s `finish` and by the supervisor. The caller passes: the top; a **classify** callback (given the top's `OverlayMeta`, returns the `ClassifiedBase`); a **compose** callback (given the classified base's source, returns the view the layer is sealed and hashed over); an optional supplied base digest; whether to seal, with an `Option<Instant>` deadline for the root flock (`None` is `sandbox run`'s unbounded acquire; the supervisor passes `Some` from step 3 on, so step 2b adds no variant without a production user; sweep 2 Claude N7); whether to pack (the bundle path and the journal to include); the manifest and journal-summary paths; and a **`&mut FinalizeProgress`** that `finalize_top` updates as each phase completes, so it survives an error from a later phase (sweep 1 Codex B2). In R1c-1 it holds `packed`, set the moment `pack` returns `Ok`; a try that finds it set skips phase 3. `sandbox run` passes a fresh one; the supervisor keeps one per attempt. It returns the fsck result, the canonical hash and change count, the meta-derived `patch_hash` fields, the manifest path, the journal summary and the bundle path, which is what `sandbox run`'s report reads (`run.rs:1186-1192`); step 3 adds the seal outcome (`layer_digest`, `sealed_at`) with the supervisor, its only reader, so step 2b leaves no field unread (sweep 3 Claude N2).

Phases, in `sandbox run`'s order (row 3):

1. **fsck**: `fsck(top, repair = !sealed)`; a top sealed by an earlier try is checked read-only (row 5). It must be clean. This phase is its own function and `FinalizeProgress` is the place its first `repaired:N` will be kept (the R1c-2 seam for partial fsck progress); R1c-1 reports the current try's result.
2. **Classify, gate, compose, seal.** When sealing: `SealOperation::acquire` or `acquire_until` (`WouldBlock` at the deadline), then `finish_if_sealed`; under the flock, `OverlayMeta::read`, **classify**, **`gate_base`** with `force_base_mismatch: false`, **then compose**, then `SealOperation::seal`, which consumes the guard. A top sealed by an earlier try is still classified, gated and composed (pack and hash need the view). Without sealing: classify, gate, compose, no lock. Gating before composing keeps today's errors: a changed base is refused with the gate's text before any bundle lower is copied or verified (Codex note; T1).
3. **Pack** unless `progress.packed`, with the base still open (`include_journal` when there is a journal); `progress.packed` is set as soon as it returns `Ok`, before phase 4 can fail, so a retry never packs onto its own bundle (row 20).
4. **Hash and outputs**: `change_set` and `canonical_hash` with `Normalize::Strict`, unchanged; the manifest and journal summary (both overwritten); `OverlayMeta::read`.

`sandbox run` keeps its classification (`classify_base(Some(&args.base), …)`), its `compose` of `args.lower`, no deadline, its sidecar paths and `--base-digest`, and builds today's JSON from the result plus its own fields; `ProgressToStderr` stays around its call in `run.rs`, because it redirects the whole process's fd 1 (`diff.rs:217-249`). Classification moves under the root flock when sealing, which is `SealOperation`'s contract (`overlay_seal.rs:335-336`) and changes no report byte.

**`acquire_until(dir, deadline: Option<Instant>)`**: `SealCommitGuard::acquire_until(dir, deadline)`, with `acquire` as `acquire_until(dir, None)`, unchanged; `SealOperation::acquire_until(dir, deadline)` of the same shape beside `acquire`, which `finalize_top` calls with the caller's deadline; the stub twin returns the same `unsupported` error.

**Stop** (`Mounter::stop(attempt, FINALIZE_WAIT)`; Linux only, since the platform rule ran at step 0; decided by the kernel, no namespace scan; ruling 7):
1. If `attempt.path` is mounted, run the helper `<binary> -u -- PATH` with `RUST_LOG=off` in its environment and its stderr piped, bounded at 3 s by `wait_bounded`. Its logger starts before the `-u` branch (`main.rs:1692-1693`), so without that a daemon run at debug level could fill the pipe and stall the helper until its kill (run 2 sweep 3 Claude N9); the error line is an `eprintln!` and still appears, and the one or two lines left are read after the helper exited or was killed; `wait_bounded` kills and reaps it at the bound. On Linux the helper runs `fusermount3 -u PATH` (or `fusermount -u PATH`) and retries it for about 1 s while the kernel answers `EBUSY`; it never passes `-z` or a force flag (row 25). Nothing else is run: no `fusermount3 -u -z`, `umount -l` or `umount -f`. Then the mount table decides:
   - **not mounted:** go on to step 2;
   - **still mounted, and the helper's last stderr line is the busy error:** **`Busy`**. `ratarmount_fuse::is_busy_unmount_error(line)`, a plain string function with no `cfg` (so `daemon.rs` compiles on every platform, although only Linux reaches it), recognizes it from its end only, beside the format it reads (`ratarmount-fuse/src/lib.rs:4139-4151`, under `cfg(not(target_os = "macos"))`): the `fusermount` diagnostic ends `: Device or resource busy` or `: Resource busy` (musl), followed by ` (busy)` or ` (still busy after N attempts over ~Xms)`, so an echoed path containing those words or a newline cannot fool it. Nothing else changes: the status stays `ready` (or `crashed`) and the attempt stays mounted (Keystone #6);
   - **still mounted after any other failure** (no `fusermount3`, `Operation not permitted`, or a helper killed at its 3 s bound): **`Failed { detail }`**, `io` naming the helper's last line or the bound ("cannot unmount attempt ID: DETAIL; nothing was changed"), with the status and the mount unchanged. A `fusermount3` that a killed helper started may still unmount later; that is harmless, because every try decides from the mount table again.
2. Whether to wait for a child comes from `ProcessMounter`'s child registry, never from the status (a `crashed` attempt can have a live child, row 10). A recorded child is waited for without a signal, up to `FINALIZE_WAIT = min(--timeout, 10 s)`. Exited: **`Stopped { exit }`**. `ProcessMounter` keeps every reaped child's `ExitStatus` until `cleanup`, from `poll` (which today drops it, `process.rs:276-278`) and from `stop`, so a child `supervise()` reaped earlier still reports its status; none ever recorded is `Stopped { exit: None }`, which step 4b treats as unclean. Still alive: **`Detaching`** (another mount of the superblock keeps the child serving; `writers_active` with "the mount process has not exited after the unmount; another mount namespace may hold the attempt; retry").

`Busy` and `Detaching` give `writers_active`, `Failed` gives `io`; nothing is sealed. Writes reach the overlay only through the child, so seal never runs while a FUSE writer can exist. A retry of an attempt a previous try left `Detaching` checks its child once with `try_wait` and does not wait again (sweep 1 Claude N2). Each `Busy` answer still costs the serial daemon up to the helper's 3 s, and the first `Detaching` answer up to `FINALIZE_WAIT`; the docs tell harnesses to stop their container before finalizing and to back off (§5.12). `Detaching` is what a premature finalize of a Docker attempt gets: `docker run -v` gives the container its own copy of the mount, so the daemon's unmount removes only the host mount, and the attempt's path is gone for the harness while the container keeps writing through the child; once the container stops, a retry seals those writes too (sweep 1 Claude N3). `stop` never runs `-z`, `umount -l`, a force flag or a signal to the FUSE child; `destroy` keeps `cleanup`'s kill-and-lazy policy, also for `finalizing` attempts. `supervise()` polls only `starting` and `ready`. `deleted_paths` keeps today's rule for the v1 statuses (the inspection socket for `starting` and `ready`, the offline database for `crashed`, `process.rs:287-294`), and for a `finalizing` attempt uses the socket while its child is alive (after a `Detaching` answer the child still holds its overlay database exclusively, `docs/sandbox.md:2665-2667`), the offline database once it exited, so `diff` and `stats` keep working in between (sweep 4 Claude N4).

**`status` inspection command.** `inspection::start` also takes the child's `Option<Arc<OverlayQuota>>` (`main.rs:2641`); `status` upgrades the overlay first, like `deleted_paths`, and answers one JSON line `{"erofs_denied":N}` from `quota.usage().erofs_denied` (`QuotaUsage`, `overlay_policy.rs:432-438`; 0 without a policy). R1b's client reads one newline-terminated JSON value (`inspection.rs:147-187`), which the multi-line `status_text()` is not (sweep 4 Claude N1, Codex N3), so the reply is structured and the client decodes it as such. A dropped overlay ends the connection without an answer, and the client reports an error.

**Report** (source doc `:118`): `status`, `attempt` (`{id, base, path, overlay_dir, status}` with final paths), `patch_hash` (as `sandbox run`'s, which carries `stack` and `base_digest_state`), `layer_digest`, `stack_digest`, `fsck_result`, `bytes_written`, `erofs_denied`, `manifest_path`, `journal_summary`, `bundle`. A retained report names `retained/ID/…` paths.

**Request IDs (Keystone #6, ruling 5).** The same ID and body re-run until `done`, each time on the stored target only; a `done` record replays its report byte for byte without touching the attempt; another body (`pack` flipped, another `id`) is `idempotency_conflict` in every state. A retry whose target was destroyed answers `not_found`, also when its ID has since been drawn for a new attempt, whose instance differs; the new attempt is never touched. Without an ID, the fast path makes a repeated finalize safe.

### 5.5 Scope preflight (rulings 4 and 7, and the base rule)

One check, run at `new` with `retain: true` after the capacity and policy checks and before R1b's lower validation (only the retained record preflight and the durability preflight's lower half run right after that validation, since they need the canonical lower paths), always before `ram_root()`, R1a's request record preflight, any attempt directory or spawn; and at `finalize` step 2, before the stop. Every refusal is `invalid_request` naming the base (the platform rule names the platform, the durability preflight the path), except the `retain`-only codes below:

- **Platform rule (ruling 7), first:** on any platform other than Linux, "finalize and retain are supported on Linux only; the sandbox supervisor is Linux only". `serve` already refuses to start there (`unsupported`, `daemon.rs:1285-1291`), so this rule guards the in-process callers (a `Supervisor` built directly, as the unit tests do on macOS). It is `cfg!(target_os = "linux")` in `daemon.rs`, a boolean that N4 permits in any file (no target predicate; row 26), with a `#[cfg(test)]` thread-local override so a Linux test drives the other branch (T24). It runs before anything is resolved or recorded (run 2 sweep 5 Claude N5): at finalize as step 0, and for `new` with `retain` in R1a's request-ID layer before `begin` (it needs only the request body) as well as at the head of this preflight for an ID-less `new`. So off Linux nothing is stopped, spawned, created or appended for these two requests, and every finalize is `invalid_request`, one naming an unknown ID included; v1 and every other v2 request behave as today on every platform.
- **Base rule:** no `binds`, not `recursive`, a source that is an absolute path or a `git:///` URL (R1b's private `check_base`, `lowers.rs:171-192`, made `pub(crate)` in step 3 and given the operation's name for its messages, so a refusal says "finalize" or "retain", not "lowers"; sweep 3 Claude N5), and no `git_synthetic_head` ("register the base without `git_synthetic_head` to finalize or retain it"; row 15).
- **Archive rule (ruling 4):** a source that is a regular file must have a prepared index, found by `ratarmount_index::resolve_prepared_index_location(source, None, &[state/indexes/<base>])` and opened with `SqliteIndex::open_lookup` (which creates nothing), whose `backend_name()` is `Some("SQLiteIndexedTar")` (`ratarmount_formats_tar::BACKEND_NAME`), as plain and compressed TAR (`.tar.zst`, `.tar.gz`, the documented sandbox base, `docs/sandbox.md:26`) both record: "base X is indexed by ZipMountSource, not as a TAR archive; finalize and retain support TAR archives only". An index with no `backendName` (a single compressed file, `factory_prepared_tests.rs:346-354`) gets "base X has no TAR index; …", and a missing or unreadable index "base X has no prepared index; …" (sweep 3 Claude N3). Directory and Git sources need no index.
- **Durability preflight (ruling 6; run 2 sweeps 1–4: Codex B1 and B2, Claude B1, N1–N5 and N10, Codex N2), last; at finalize its lower half runs right after step 3:** it makes S refuse nothing it accepted, short of a change in between, a new fsync error, an unreadable node inside a tree or a writable node inside a lower (documented limits, §5.12). The trees are each recorded lower path, `attempts/ID` (`retained/ID` on the fast path), `indexes/<base>/` and a tmpfs attempt's `overlay_dir`; for each:
  - **Types.** The `fstatfs` type of the root and of its parent `P1` is on the allowlist: ext2/3/4 (`0xEF53`), xfs (`0x58465342`), btrfs (`0x9123683E`) or tmpfs (`0x01021994`) (row 30). Read-only images (squashfs `0x73717368`, erofs `0xE0F5E1E2`, iso9660 `0x9660`) are refused like any other type: the image file behind them is what would need the sync (run 2 sweep 4 Codex B2). Every directory S syncs is a node of a tree, the tree's parent, or in its chain on the parent's device (§5.6 S3), so a lower that is the root of its own filesystem is refused here when its parent is off the allowlist, since finalize syncs that parent too (ruling 1+2, "then its parent"): "the parent /layers of lower /layers/A is on overlayfs; mount the volume at /layers or above".
  - **Chains.** Each directory of the chain, found as S finds it (its device read with `statat(.., SYMLINK_NOFOLLOW)` by path, which needs only search permission, so an unreadable directory on another device just ends the chain; Claude N3), opens `O_RDONLY | O_DIRECTORY | O_NOFOLLOW` as S will open it, so an unreadable ancestor (T20.6's mode-0300 `P`) is refused before anything is sealed (Claude N4).
  - **Mounts.** No mount point in `/proc/self/mountinfo` (`process::mountpoints`, `process.rs:391-401`) lies strictly below the root (a component-wise prefix that is not the root itself: a lower whose root is a mount point is accepted, its parent being judged by the type rule; run 2 sweep 4 Claude N1), other than the attempt's own `attempts/ID/mnt` itself, which the stop removes. A mount below `attempts/ID/mnt` is refused here too ("unmount M first; finalize never unmounts it for you"): the stop unmounts only `mnt` itself, and the kernel answers `EBUSY` while a child mount remains, which would otherwise read as `writers_active` on every try (run 2 sweep 5 Claude N1; `cleanup` unmounts children, `process.rs:304-326`, but `stop` never does, and never lazily). A mount inside a tree is the only way its nodes can be on another filesystem, a bind-mounted overlayfs file that reports the tree's device included (Codex B1); S refuses one too, by device or by its own `fstatfs` (§5.6). One layout has a second device without a mount: a btrfs subvolume or snapshot nested in a user's directory lower (run 2 sweep 5 Claude N3). The daemon's own trees never hold one; the preflight does not walk lowers to find one, so S's device check refuses it after the seal with its mismatch message (which names the path and both devices), and the docs say to keep subvolumes out of lowers (§5.12, Risk 12).
  - **Lower roots.** A lower's root carries no write bit (S1(a)'s first check, made here before the stop as well): a killed fill and an interrupted `overlay unseal` both leave the root writable (§5.6), so they are refused, with `lower_changed` and the `overlay seal` remedy, before anything is sealed; only a writable node below a read-only root reaches S.
  - **Poison** (run 2 sweep 4 Claude N2). No root, parent or chain directory is on a device a failed fsync poisoned (§5.6), so after a poisoning a finalize touching that device answers `io` (the poisoning message) here, before its stop, fsck repair, seal or pack, instead of in S; S's own check stays the backstop.
  - **Opens.** The preflight opens every directory it checks through `overlay_pack::open_root` (made `pub(crate)`; its reviewed statement `IR-B0046-M01` is unchanged), which uses the flags S uses (`RDONLY | DIRECTORY | NOFOLLOW | CLOEXEC`), so no new inventory site (run 2 sweep 4 Claude N4; §5.10).

  A refusal is `invalid_request` naming the path and why (a poisoned device is `io`, a writable lower root `lower_changed`): "PATH is on TYPE, whose fsync finalize cannot rely on (overlayfs skips files that exist only in a lower layer; FUSE may drop it); keep the state directory, the bundle cache and every lower, and the directory each one sits in, on ext4, xfs, btrfs or tmpfs (inside a container, a volume mounted at or above that directory)", or "PATH cannot be opened", or "PATH has a mount inside it at M". At finalize, the lower half runs after step 3, so a lower a cleaner deleted is `lower_changed` from R1b's re-read first, never a preflight error (Claude N5). At `new` with `retain` the same checks run for `attempts/` and `indexes/<base>/` and their chains before anything starts, and right after R1b's validation, which produces canonical paths before the RAM root and any spawn (`daemon.rs:856-869`), for each lower: a directory lower's canonical root; for a bundle position, the cache directory the child will extract into, not the bundle file R1b validated (Codex N2), that is `$XDG_CACHE_HOME/ratarmount/layers`, or `$HOME/.cache/ratarmount/layers` (`overlay_pack.rs:1812-1817`; the child inherits the daemon's environment), checked through its deepest existing ancestor when it does not exist yet, since the child will create it there. A plain attempt (no `retain`) on such storage is still accepted at `new` and refused only at finalize, before its stop (documented, §5.12; Claude N10). Finalize's preflight is the authoritative one, and S checks again, as a backstop, every descriptor it syncs (§5.6). The checks use the `daemon.rs` filesystem-type probe (§5.10).
- **`retain` only:** `overlay: "tmpfs"` (the RAM overlay lives outside `attempts/ID`, `daemon.rs:956-958`, so the commit rename would not move it); `capacity` past `--max-retained` (§5.7); `io` while `retained.jsonl` is `Broken`; and the **record preflight** (sweep 1 Claude N5), modelled on `record_preflight` (`daemon.rs:742-775`): the `retained.jsonl` line an attempt of the batch would write is measured with the real state paths, R1b's canonical lower paths, a bundle position's cache path at its fixed length (the cache root, canonicalized as the child canonicalizes the path it records, `ratarmount-compositing/src/lower_stack.rs:173-175`, through its deepest existing ancestor when it does not exist yet, plus 64 hex digits; sweep 2 Claude N3), a full `over` and a report with every field at its widest, and over 64 KiB the request is `capacity` before any attempt exists, with a message naming the bound and the line's size ("the retained record of this stack would take N bytes, over its 64 KiB bound; use fewer or shorter lower paths").

v1 is unchanged: `create_base` and v1 `new`, `list`, `diff`, `stats` and `destroy` behave as today on every base.

### 5.6 Durability in every finalize, and the retain commit (ruling 1+2)

**Step S runs in every finalize** (ruling 1+2 as written; sweep 1 Codex B3; run 2 sweep 1 Claude N5): every try of every finalize, with or without `retain`, after `finalize_top` succeeded and before its report is returned or its commit starts, whether its bundle lowers were fresh fills or cache hits and whatever built a cache entry; and on the fast path for an attempt already `finalized` or `retained`, before the stored report is returned. Nothing is skipped because an earlier finalize already synced an entry, and there is no generation marker. The attempt itself is sealed and immutable by then, but what its records name need not be: a cleaner can purge a bundle cache entry, and a later hit refills that path with a new, unsynced inode (`overlay_pack.rs:2008-2034`). Only R1a's replay of a `done` record returns its stored answer without running anything (R1a's contract, unchanged); a client that wants a fresh durability check sends a new finalize. The child has exited and nothing is mounted at `attempts/ID/mnt`. S, in order:

1. **Each lower the child took** (R1b's records, bottom first): take the layer's **entry lock** (`overlay_pack::lock_layer_entry`: an exclusive `flock` on an `open_root` descriptor of the recorded path, polled until S's one deadline, `FINALIZE_WAIT` after S started, shared by all lowers, so 32 lowers cannot hold the serial daemon 32 times over; run 2 sweep 3 Claude N8; `WouldBlock` → `in_use`). Under it, in this order (ruling 6): **(a)** no regular file or directory of the lower carries a write bit, for every lower however it was supplied (sweep 4 Codex B1; extended to every node in run 2 sweep 4 Codex B1): the locked root is checked before anything else, and every other regular file and directory on the descriptor the walk `fstat`s, before its fsync, because an `overlay unseal` killed after its mode walk leaves writable descendants under an unchanged identity (§5.6, the cache hit) and a root made read-only again by hand would hide them. A cache entry left by a publisher killed between its rename and its restore can also be named as a directory lower, and R1b's directory read checks only the seal metadata (`lowers.rs:322-334`). Seal and `finalize_stage` both leave a root without write bits (row 12), and seal strips the root last, after its sentinel and its children (`overlay_seal.rs:546-551`), so a writable node is an unfinished publication, an interrupted seal or unseal, or a changed mode: `lower_changed` with the remedy, and nothing after it is synced ("lower X has a writable PATH, so it is not a completely published or sealed layer; run `ratarmount overlay seal X`, which finishes an interrupted seal or publication by restoring its sentinel and read-only modes, then retry"; sweep 4 Claude N5, corrected in sweep 5 Claude N2: `overlay seal` of a sealed layer runs `finish_recorded_seal`, `overlay_seal.rs:321-333`, while a `chmod a-w` of the root alone would leave an interrupted seal's children writable and its sentinel missing). A writable root stops S before anything is synced; a writable node found later stops it before that node's fsync (the earlier fsyncs were of clean data and harm nothing). This reverts sweep 3's bundle-only check (§10.8). **(b)** The lower's **identity is checked again** (ruling 6; run 1 skeptic sweep 6 N1): R1b's `lowers::recorded_layers` on this one record (`read_no_recovery`: still sealed, with the recorded `layer_digest` and `sealed_at`; `lowers.rs:543-567`), and then the recorded path must still name the locked inode (the root descriptor's `fstat` and the path's `lstat` give one `(dev, ino)`). A failure or a difference is `lower_changed`, with R1b's message or "lower X was replaced after its sync started", and nothing is synced. The re-read takes no flock (`lowers.rs:5-9`), only SQLite's SHARED lock, and its connection is closed before (c), so the walk's admitted opens never meet a registered database. The entry lock is the layer's overlay root flock: the exclusive `flock` on an `O_RDONLY | O_DIRECTORY` descriptor of the layer root that `SealCommitGuard` takes for seal, unseal and commit (row 2; the #240 lock, which `SealOperation::acquire_until` takes for the top in step 6), so no `overlay unseal`, edit and re-seal of the layer can run between (b) and (c) (§5.9). No lock file is involved: the `.ratarmount.overlay.seal-commit.lock` file is obsolete, ignored and left in place (`docs/sandbox.md:629-631`), and S neither creates, opens nor waits on it (Keystone approval note (2)). **(c)** `overlay_pack::sync_tree` from that locked descriptor (below), in post-order: each directory's regular files, then its subdirectories the same way, then the directory itself, ending with the layer root; then `sync_dir(parent of the layer)`; release. This is "the layer files, then the destination directory, then its parent", for bundle cache entries and directory lowers alike. A node the daemon cannot open fails the finalize with `io` naming it (sweep 2 Claude N6). **No fsync error is exempt** (run 2 sweep 4 Codex B2). Run 1 counted an `EINVAL` from a squashfs, erofs or iso9660 lower as synced, since those filesystems have no `fsync` method and hold no dirty data; but their image file, read by a loop device through the page cache (`drivers/block/loop.c`, `vfs_iter_read`), may itself be freshly copied and unsynced, and nothing in S syncs it. Those types are now off the allowlist (§5.5), refused before the stop, so no lower S reaches can answer `EINVAL`, and every fsync error, `EINVAL` and `EROFS` included, poisons (`EROFS` never was exempt: ext4 answers it after aborting on an error and remounting read-only, when data may be lost; sweep 5 Codex B1). Every fsync in S runs on a descriptor S opened, so every error carries its raw errno. The type probe is a Linux `fstatfs` beside `verify_tmpfs` in `daemon.rs` (`:1124-1140`), with a non-Linux twin that answers "unknown" (§5.10); S passes it to `sync_tree`, so tests inject it.
2. **The attempt's own tree** `attempts/ID`: `sync_tree` (the overlay payload and database, manifest, summary, journal, bundle, then the directories, ending with `attempts/ID`); for a tmpfs attempt also its `overlay_dir` (`ram/ID`, outside the tree), where an fsync costs nothing. **And the base's prepared state** `indexes/<base>/` (sweep 5 Claude N3): `sync_tree`, for every base kind. It is the daemon's own artifact, not the user's base: a retained layer over an archive can be mounted, or used as a lower, only through that index, since workers run `--no-recreate-index`; and nothing made it durable, because index builds run `synchronous = OFF` (`ratarmount-index/src/lib.rs:1346`), `publish_tmp` renames without syncing the directory (`:1997-1998`), and neither `finalize_prepared` nor `atomic_json` syncs `indexes/` or `indexes/<base>/`.
3. **Chains** (sweep 2 Codex B1; run 2 sweep 2 Claude B1): the chain of a tree is its parent `P1` and every directory above `P1` whose device, read with `statat(.., SYMLINK_NOFOLLOW)` by its path (search permission only), is `P1`'s, up to the root of `P1`'s filesystem; the first directory on another device ends the chain before it is opened, type-checked or synced (it is no mismatch, and an unreadable directory there costs nothing; run 2 sweep 3 Claude N3). Only chain directories are opened (`O_DIRECTORY | O_NOFOLLOW`, by `sync_dir`), and the preflight opened each of them before the stop (§5.5). A lower's `P1` is synced in S1(c) under its entry lock, even when the lower is the root of its own filesystem and `P1` is on another (ruling 1+2, "then its parent"); the rest of every chain, and the whole chains of `attempts/ID`, `indexes/<base>/` and a RAM `overlay_dir`, are deduplicated and synced deepest first through `sync_dir` in its S mode. Every directory of a chain is on `P1`'s filesystem, whose type the scope preflight checked (§5.5). A cache hierarchy that `cached_lower_in` created recursively (`$XDG_CACHE_HOME/ratarmount/layers`, `overlay_pack.rs:1973-1976`) is then durable from the entry up, and so is a state directory that `serve` created (`daemon.rs:1294`). No step decides which ancestors are new, so all of them are synced, and every level is strict (sweep 3 Codex B1): an ancestor that cannot be opened or synced, an unreadable one included (a write-and-search directory such as mode 0300 lets the recursive cache create add entries the daemon then cannot fsync), fails the finalize: the preflight refuses an unreadable one before the stop, naming it (`invalid_request`; run 2 sweep 3 Claude N4), and S answers any failure there with `io` naming it, before the report or the `retained` record. Every chain directory of the state directory, the bundle cache and each lower, up to its filesystem's root, must therefore be readable by the daemon user (documented, §5.12).
4. **Without `retain`:** status `finalized` and the report. **With `retain`:** the commit R2–R5, whose R4 syncs the tree's new and old parents.

| # | Step of the commit (`retain` only) | On failure |
| --- | --- | --- |
| R1 | **S** (above) | `io`, nothing recorded or renamed; a failed fsync poisons its filesystem; an entry-lock deadline answers `in_use`, a changed lower `lower_changed`, a device or type mismatch or a filesystem off the allowlist `io`, and none of these poisons anything |
| R2 | Append the `retained` record (§5.2, §5.7) | engine truncation, else `Broken`; `io` |
| R3 | `rename_no_replace(attempts/ID → retained/ID)` on absolute paths (the two-directory form, §5.8). On success the entry and R1b's records leave the attempts map and `taken_lowers` at once and enter the retained map, not yet acknowledged, so memory always names where the tree is; the Mounter forgets the attempt's child entry and kept exit status (`Mounter::forget_child`, which unmounts and signals nothing; the child has exited), so `ProcessMounter`'s registry keeps no key for a path that has moved (sweep 5 Claude N7) | append `aborted`; `io`; status `finalizing`. A filesystem without `RENAME_NOREPLACE` answers `EINVAL` here on every try, after the whole finalize: the message says so (§5.8) |
| R4 | `sync_dir(retained/)`, then `sync_dir(attempts/)` (Keystone #2's parent-directory fsync; the state root and everything above it were synced in S, and the rename changes neither); the entry becomes `retained` | `io`; the entry stays unacknowledged, listed as `finalizing` by `list {all: true}` only: it left the attempts map at R3, so v1 `list` and v2 `list` without `all` no longer show it (run 2 sweep 1 Claude N6). A failed fsync poisons the state filesystem (below), so this entry and every later finalize answer `io` until a restart; any other R4 error (an open failure) poisons nothing, and a retry of the finalize re-runs R4 and R5 |

**The commit point** is the rename made durable by R4; the content (R1) and the record (R2) were durable before it. A crash before the rename leaves `attempts/ID`, which `reconcile` deletes (§5.8), and the request resolves to `interrupted` (Keystone #2). A stray `retained/ID` fails R3 with `EEXIST`; nothing is replaced. Every tree in `retained/` therefore has a live record, and a live record whose tree is not in `retained/` names a commit that never happened: R3's `aborted` line ends it when it can be written, and otherwise it stays live, reserving its ID and one slot, until R1c-2's recovery aborts it. `destroy` and `reconcile` delete a tree in `attempts/` as for any attempt. Nothing in R1c-1 deletes a tree in `retained/` (sweep 3 Claude N9): `destroy {id}` of any retained-map entry, an unacknowledged one included, is `retained`, so no crash can leave a partial tree that a live record names. An unacknowledged entry whose R4 cannot complete (its filesystem poisoned) stays listed as `finalizing` (by `list {all: true}`) and refused as a lower until R1c-2's `forget`, or until an operator removes it with the daemon stopped (§5.13).

**`overlay_pack::sync_tree`, every node checked (ruling 6).** It sits beside `remove_contents` and `seal_directories`, which already walk layers by descriptor (row 13). A tree's **expected filesystem** is its root's device, read with `fstat` from the root descriptor: S1's locked descriptor, or `open_root` of `attempts/ID` (`retained/ID` on the fast path), `indexes/<base>/` or a RAM `overlay_dir`. That device must not be poisoned, and the root's `fstatfs` type must be on §5.5's allowlist (run 2 sweep 1 Codex B1). Every other node is checked on its own descriptor below, its `fstatfs` included, because a shared device does not imply a shared filesystem: a lower-only overlayfs file bind-mounted into an ext4 tree reports the ext4 device (`xino=off`) while its `fsync` reaches nothing (run 2 sweep 3 Codex B1).
- **Listing.** For each entry of a directory (`Dir::read_from`), `host_stat::statat(.., SYMLINK_NOFOLLOW)` gives its type, `(dev, ino)` and device. Every entry's device must be the expected one, symlinks, sockets (a stale `inspect.sock`), FIFOs and device nodes included; those four are not opened or synced, since their names are covered by their directory's fsync. A name that is not UTF-8 fails S with `io` naming its directory, as `collect` refuses one for pack (`overlay_pack.rs:150`), because the admitted open takes a `&str` (`:77`); no entry is ever skipped silently (run 2 sweep 1 Claude N7).
- **Opening.** A directory is opened with `host::openat(dir, name, directory_flags())` (`RDONLY | DIRECTORY | NOFOLLOW | CLOEXEC`), a regular file through the admitted open `openat_admitted(dir, name, regular_flags())` (`RDONLY | NOFOLLOW | NONBLOCK | CLOEXEC`; on Linux an `O_PATH` probe that keeps `O_NOFOLLOW`, an `fstat`, the refusal of an open overlay database's other name, and a `/proc/self/fd` reopen of that inode, `db_inodes.rs:237-315`). A symlink put in a node's place fails with `ELOOP`, and a FIFO opens without blocking and then fails the type check, so the serial daemon never blocks in `open(2)`.
- **Checking, on the descriptor that will be synced.** Its `fstat` must report the type and `(dev, ino)` the listing saw, its device must be the expected one, and its own `fstatfs` type must be on the allowlist, for regular files as for directories (one more system call per node, small beside the fsync). **Any mismatch is the poisoning refusal:** `io` naming the node, the device it reports and its tree's device ("PATH is on device D2, not on the filesystem of its tree (device D1); finalize syncs only trees that lie wholly on one filesystem, and an overlayfs whose layers are on different filesystems reports such devices"); the finalize stops before any further fsync, with no report and no `retained` line. A mismatch marks nothing poisoned, because no fsync failed; every later try is refused by the same check.
- **Syncing.** `fsync` on that descriptor; a directory after its children; the root last. One descriptor per directory level stays open during the walk, none per file after its fsync, and nothing below the root is opened by host path, so host path length is no limit.
- **Lock safety (#151).** S runs after `finalize_top` returned and after (b)'s connection closed, and the supervisor keeps no SQLite connection across requests (`Supervisor` holds the logs, the maps and its lock file, `daemon.rs:313-333`; R1b adds records only), so no inode the walk opens is held as a database by this process, and closing its descriptors releases no lock. An open overlay database's other name is refused by the admitted open; anything beyond that is the residual every admitted open shares (#196, `db_inodes.rs:33-36`).
- **Not the managed cursor.** Run 1 synced files through `ManagedReadCursor`, which resolves symlinks with `canonicalize`, checks the type with a path `stat` before SQLite opens the file and exposes no descriptor (`managed_read.rs:62-78`, `:688-694`): it can satisfy neither half of ruling 6.

`sync_dir(path, mode)`, the engine's directory fsync, opens with `O_RDONLY | O_DIRECTORY | O_NOFOLLOW | O_CLOEXEC` from step 3 on (sweep 2 Claude N9; today a plain `File::open`, `requests.rs:471`) and fsyncs that descriptor. It has two modes (run 2 sweep 1 Claude N3 and N4, Codex N4):
- **For S and R4** (each layer's parent, S3's ancestors, R4's `retained/` and `attempts/`): before the fsync it checks on the descriptor that it is a directory, that its device is not poisoned and that its `fstatfs` type is on §5.5's allowlist; every fsync error poisons the device (no exemption, as in `sync_tree`).
- **For the logs** (`requests.jsonl`'s and `retained.jsonl`'s directory at open and after a compaction): R1a's rules, unchanged. It consults no poisoned set and marks nothing; a failure is the log's own (`Broken`). So a poisoned state filesystem never turns R1a's compaction into a refusal; it refuses only S and R4 (§5.2 keeps the engine record-independent).

**The entry lock on the cache side** (`overlay_pack.rs`, ruling 1+2's "per-entry publish/sync completion"):
- `publish_layer` takes the exclusive lock on the stage root's descriptor it already opens, before adding write permission and renaming, and releases it after the permission restore. The staged root and the published entry are one inode, so the lock covers the entry from the moment it is visible.
- **Publication must have completed, not merely released its lock** (sweep 1 Codex B1). A publisher killed between its rename and its restore releases the lock and leaves the root writable, and a restore that fails after the rename returns an error that today's lost-race fallback (`:2028-2033`) turns into an accepting `hit`. A completed publication leaves no write bit on the root (row 12), so that is the test, made under the lock.
- **A cache hit** (the existing-destination path `:2008-2010` and the lost-race path `:2032`) opens the destination with `open_root`, takes the lock shared (waiting), and holds it through its checks and verification until it returns the path (sweep 1 Codex N4). Its first check is the publication: a root with a write bit is **refused, never repaired** (run 2 sweep 4 Codex B1), and no caller gets its path: "cache entry X is not a completely sealed layer (a fill killed between its rename and its mode restore, or an interrupted `overlay unseal`); run `ratarmount overlay seal X`, which restores its sentinel and every read-only mode, or remove X to refill it". Run 1's repair (clear the root's bits under an exclusive conversion) assumed only `publish_layer` makes a root writable; but `overlay unseal` makes the whole tree writable first and clears the seal rows and the sentinel after, in one transaction (`overlay_seal.rs:686-708`, `with_transition_modes`, `:124-136`), so an unseal killed in between leaves writable descendants under an unchanged seal identity, and verification cannot see the modes, since the layer view substitutes the recorded ones (`overlay_layer.rs:237-238`). Clearing only the root would hide that tree. `overlay seal X` finishes both states correctly (`finish_sealed`, `:635-665`). So no publish or S of that entry runs between a hit's wait and its return, a hit never returns a path whose publication had not completed, and hits of a complete entry, the common case, still run side by side under the shared lock; there is no conversion. The hit's checks and verification take no flock of their own (`immutable_meta` and `overlay_seal::verify` open the layer through SQLite and take none), so the shared hold nests nothing.
- S, under its exclusive lock, refuses a lower any regular file or directory of which carries a write bit (S1(a)), rather than changing it.
- Cache extraction never syncs. An entry made by an older ratarmount was published without the lock or a sync; every finalize that references it syncs it, like any other entry.
- `publish_layer` is also `overlay unpack`'s publish (`overlay_pack.rs:1779`), so an unpack holds the same lock across its rename and permission restore; nothing else about unpack changes.
- **A cache filesystem without `flock`** (run 2 sweep 2 Claude N3): when `flock` fails with `ENOSYS`, `ENOLCK` or `EOPNOTSUPP` (an NFS home without lock support, Lustre without `-o flock`), `publish_layer` and a hit proceed without the lock, as every `--lower` bundle mount and `overlay unpack` does today, logging once per process; the hit's publication check still runs. Those mounts outside the sandbox path keep working. S never meets the case: every filesystem on its allowlist supports `flock`, and S answers any lock failure other than `WouldBlock` with `io`.
- A sealed layer root's `flock` is its #240 overlay root flock (row 2; `SealCommitGuard`'s directory flock, never the obsolete `.ratarmount.overlay.seal-commit.lock` file): the entry lock of a directory lower or a cache entry serializes with a seal, unseal or commit of that layer and with nothing else. S never holds two such locks; only `sandbox run` nests one, a cache hit's inside its top's, which cannot cycle (§5.9).

**Poisoning, by filesystem** (sweep 4 Codex B2). After an fsync error the kernel may have dropped the dirty data and reported the error once, so a later fsync can return 0 for lost data, and not only through the same name: the same inode reached as a hard link in another lower, or a shared directory (a cache's `layers/`, a common ancestor), syncs "successfully" afterwards. An error returned by any fsync in S or R4 therefore poisons, in memory, the whole filesystem it happened on (its `st_dev`). From then on, every S that would sync anything on that filesystem answers `io`, under any request ID or none ("a sync on the filesystem of PATH failed earlier in this daemon run, so its data may be lost; every finalize on it is refused until the daemon restarts, and a restart discards every unfinalized attempt; check the storage first"; sweep 5 Claude N6); the attempt that saw the error is therefore never finalized or retained in this run either. **How S checks** (sweep 5 Claude N1; ruling 6): before its first fsync, S checks the device of every tree root it will walk (each lower root, `attempts/ID`, `indexes/<base>/`, a RAM `overlay_dir`) and of every S3 ancestor against the poisoned set, and refuses if any is poisoned. Every other node's device equals its tree root's, or the node is refused as a mismatch before its fsync, so a failed fsync poisons exactly the device of the node it failed on, which is its tree's. A file that reports a device its directories do not (an overlayfs with layers on different filesystems; run 1 Codex sweep 6 B2) is that mismatch, whether or not its device is poisoned, so a poisoned device cannot be reached through a view whose directories report another one; a mount inside a layer is a mismatch too. An open or listing error, an entry-lock deadline, a writable or changed lower, a device or type mismatch, and a filesystem off the allowlist poison nothing. The logs' own fsyncs neither consult nor add marks (`sync_dir`'s log mode). Marks are not persisted: a restart starts with none (Risk 3).

### 5.7 Retained attempts: in a run, across a restart, and their identity (ruling 3)

- **The retained map** (this run): ID → the attempt with `retained/ID/…` paths, its report, R1b's records, its attempt state (instance and `over` included), and whether R4 completed (acknowledged).
- **`list`**: v2 `list` without `all` answers as v1 does; with `all: true` it shows attempts and then retained entries in ID order; v1 is unchanged.
- **`diff`, `stats`** find an ID in the attempts map, then the retained map. A `finalized` or `retained` attempt is read offline; `diff` classifies its base (as §5.4 step 6) and runs `gate_base` with `force_base_mismatch: false`, which writes nothing, before composing the recorded layers; a gate refusal is `diff_failed` (the CLI `diff` gates too, `diff.rs:383-389`), and a failed open stays `base_open_failed`, as today.
- **`destroy {id}`** of a retained-map entry, acknowledged or not, is `retained` ("attempt ID is retained; retained attempts are never destroyed"; §5.6). `destroy {base}`, `shutdown` and `serve`'s final `destroy_all` (`daemon.rs:1354`) iterate the attempts map only.
- **The attempt's state** (sweep 3 Claude N8; one map since sweep 4, Claude N3 and Codex N4): the v1 `Attempt` shape has no room for it, and R1b keeps no per-attempt journal state (`daemon.rs:313-333`), so one side map `attempt_state: BTreeMap<String, AttemptState>` holds everything R1c-1 keeps per attempt: the plan (its **instance**, created with `retain`, with a journal, and `over`), written when `new_attempts` records the attempt, before its spawn. The instance (ruling 5) is 32 lowercase hex digits: `hash_one((counter, 0))` and `hash_one((counter, 1))` of one std `RandomState` made at `Supervisor::open` (OS-seeded keys; no new dependency), over a per-daemon counter that only increases, never derived from the ID, a time or an inode number (inode numbers are reused, #199). The map also holds the finalize state (`FinalizeProgress`, the first `bytes_written`, the last `erofs_denied`, the journal-failure mark of step 4b, the stored report). It is read by finalize, by S and by the `--max-retained` count; `destroy` removes it with the attempt, as it removes `taken_lowers` (`daemon.rs:1092-1103`), and the commit moves it into the retained entry. Nothing else is kept per attempt ID, so an ID drawn again starts clean, with a new instance that no earlier request record names (ruling 5). A journaled attempt whose `attempts/ID/journal.jsonl` is missing at finalize answers `io`, never "no journal".
- **As a lower** (R1b's reserved exception): the place rule accepts exactly `<state>/retained/<ID>/overlay` for an acknowledged entry of the retained map, matched lexically before any lookup, with `retained/`, `retained/ID` and `retained/ID/overlay` each a real directory (`symlink_metadata`, no symlink); then R1b's directory-lower checks apply unchanged (sealed, digest, stack and base agreement, re-check after ready). `retained/ID/bundle.tar.zst` and every other path under the state root stay refused ("use retained/ID/overlay"). A layer retained over a directory base records `weak`, which R1b refuses as a lower; TAR (sealed as `strong`, `overlay_seal.rs:443-451`) and Git (`git-tree`) layers branch.
- **`over`**: the IDs whose `retained/<ID>/overlay` a `new` named as a lower, kept in the attempt's state before its spawn and copied into the `retained.jsonl` line.
- **One set decides capacity and reservation** (run 2 sweep 1 Codex B2). `held` is the union, each ID once, of: every ID with a live record in `retained.jsonl`, read from the log itself rather than from a set taken at start, so it includes this run's records and a record whose rename never happened (R2 durable, R3 and its `aborted` append failed), also after that attempt was destroyed; the names `Supervisor::open` found under `retained/` without a record; and the IDs of live attempts created with `retain`. The retained map is a subset of the first part: R2 precedes R3, and `aborted` is written only when the rename did not happen.
- **`--max-retained N`** (default 4096, `0..=4096`, so live lines stay within 256 MiB, §5.2; 0 refuses `retain`): a `new` with `retain` needs `|held| + count ≤ N`, else `capacity`. Retained entries never count toward `--max-attempts` (Keystone #1).
- **Reserved IDs:** the redraw check (`daemon.rs:938`) also refuses every ID in `held`, and R1a's reservation also covers a finalize `done` record's target (§5.2); `running`, `retryable` and `failed` finalize records reserve nothing, because their target carries the instance. An ID in `held` that names neither a live attempt nor a retained-map entry (a record from before a restart, a name found under `retained/`, or an orphan record of this run) is not served: `finalize` (before any request record, §5.4 step 1), `diff`, `stats` and use as a lower answer `invalid_request` ("attempt ID has a retained record that this daemon does not serve: it was retained before a restart, or its commit did not complete; this release cannot serve it"), and `destroy` answers `retained`. It keeps its ID and its slot until R1c-2's recovery or `forget` ends the record. The reviewed `tempdir_in` statement (`IR-B0112-M01`) is untouched.
- **Restart in R1c-1** (recovery is R1c-2). `Supervisor::open`, after `RequestLog::open` (`:396`): `private_dir(retained/)`, `RetainedLog::open` (the engine's checked open, syncs and replay), then the names under `retained/` without a live record (part of `held`; a live record carries its instance, a bare name has none, so no request record's target matches it), then `reconcile`, which never enters `retained/`, then `resolve_interrupted`. These preserved entries stay on disk untouched, are in `held` (reserved and counted toward `--max-retained`, as above), and are not served: `list` omits them, and they get the not-served answers above. A record whose rename never happened stays live until R1c-2's recovery aborts it; it only holds its ID and one slot.
- **Identity (ruling 3).** Each record holds the attempt ID and its instance (the one finalize request records name, ruling 5), the base, the paths, `layer_digest`, `sealed_at`, the prefix (the child's records: each lower's path, `layer_digest` and `sealed_at`; a bundle position names its cache path) and `over`. No R1c-1 code looks a layer up by digest: the retained-lower exception and `over` resolve a requested path to an ID. R1b's stack check still compares digests to judge a stack (R1b §5.3); that is a consistency check over requested lowers, not provenance.

### 5.8 Removal of sealed trees, and the commit rename

`overlay_pack::remove_tree(path)`: `open_root`, the existing `remove_contents`, then `remove_dir` of the root, whose error reports anything left. It replaces `fs::remove_dir_all` in `reconcile`'s two loops and in `destroy`; a disk attempt is one `remove_tree` of its root (with `overlay/` inside), a RAM `overlay_dir` its own. So a crash between seal and rename cannot block the next start (Keystone #2), and a finalized tmpfs attempt can be destroyed. Mount handling is unchanged: `cleanup` still unmounts `mnt` and below first, and `remove_dir_all` also descended into a mounted directory.

`overlay_pack::rename_no_replace` takes `(old_dir: impl AsFd, from, new_dir: impl AsFd, to)` instead of one `&OwnedFd` (`overlay_pack.rs:1134`; sweep 3 Claude N7); its caller `unlink_if_same_named` (`:1188`) passes its directory twice, and the commit passes `rustix::fs::CWD` with absolute UTF-8 paths. A cross-filesystem `retained/` fails with `EXDEV` at R3 (`aborted`, `io`); there is no start-time device check. A state filesystem without `RENAME_NOREPLACE` (OpenZFS before 2.2, for one) fails R3 with `EINVAL` on every retain, only after the finalize work; the docs name the supported filesystems (ext4, xfs, btrfs, tmpfs) and the message says the filesystem lacks no-replace renames (sweep 5 Claude N4). A start-time probe is not taken: it would have to create a scratch entry and rename it to a free name, a new creation site for a check the documented limit already covers (§9).

### 5.9 Lock order (re-verified on `cf8f626`)

1. **`daemon.lock`**, held for the daemon's life (`daemon.rs:345`, `:411`): serializes every request, both logs, and every change under `attempts/` and `retained/`.
2. **Finalize:** fsck's own transaction commits first (`overlay_fsck.rs:208`); then the top's **overlay root flock** (`SealOperation::acquire_until`), then seal's **`BEGIN IMMEDIATE`** (`overlay_seal.rs:456`), released when `SealOperation::seal` returns (`:358-364`) or `finish_if_sealed` reports an earlier seal. **No archive lock:** "Seal never acquires an archive lock" (`overlay_seal.rs:276`); `docs/sandbox.md:615-618`. The archive flock belongs to commit, which takes the overlay lock first (`write_overlay.rs:7350-7363`; `docs/sandbox.md:610-611`) and which workers never reach (`--no-recreate-index` refuses overlay commits, `docs/sandbox.md:2240-2247`).
3. **S (every finalize):** one layer root flock at a time (exclusive, bounded), only after the seal returned, never while holding the top's; under it, R1b's identity re-read (ruling 6) takes only SQLite's SHARED lock on that layer's database, no flock and no write transaction (`lowers.rs:5-9`), and closes its connection before the walk; no archive lock. The seal of a lower, which takes that same root flock first (`overlay_seal.rs:409-412`), therefore cannot change the layer between the re-read and the walk.
4. **Child:** `publish_layer` holds its stage root's flock across rename and restore; a hit holds a destination's flock shared until it returns the path and never upgrades it, since a writable root is refused, not repaired (§5.6; run 2 sweep 5 Codex N2). The child opens its lowers before its top (`main.rs:2492-2521`), so it holds no other overlay root flock then.
5. **Nesting (sweep 2 Claude N4):** from step 2b `sandbox run` composes `args.lower` under its top's root flock (§5.3), so a bundle lower's hit takes that entry's flock inside the top's; `overlay seal DIR --lower BUNDLE` composes under its top's flock the same way (`overlay_cmd.rs:544-567`), so with the hit's lock it nests identically. Every nesting is the top's root flock first, then a cache entry's, and nothing takes a top's root flock while holding an entry's. It cannot cycle: `publish_layer` holds only its stage's flock and never a top's, and S takes entry flocks while holding no top's flock. T20.3 covers the wait.

## 8. Risks

1. **R1c-1 alone is not the whole feature.** A restart keeps retained trees and their IDs but does not serve them, and nothing can be forgotten through the API until R1c-2; a cut-off retaining finalize resolves to `interrupted` even when its tree survived, and stays `interrupted` after an upgrade to R1c-2, whose recovery can resolve only records still `running` at its first start (§5.13; run 1 skeptic sweep 6 N5). Recommendation: no release tag between R1c-1 and R1c-2 (Keystone decides).
2. **Sync cost.** Every finalize, retained or not, fsyncs every file of the top and of every lower, cache entries included, and their ancestors, each time (ruling 1+2 as written); XFS issues a device flush per `fsync` even for a clean file when the log shares the data device, and ext4 with barriers (its default) does too: `ext4_sync_file` sends a cache flush when the inode's transaction has already committed (run 1 skeptic sweep 6 N4). On a device with a volatile write cache, a lower with 10,000 files therefore costs about 10,000 flushes per finalize on either filesystem, and a 100,000-file prepared layer can hold the serial daemon, and every other client, for minutes (sweep 2 Claude N9). The PR times it (§7). Ruling 1+2 fixes what is synced, not which thread does it: running S on a worker thread while the attempt stays `finalizing` is an option for Keystone; skipping already-synced entries is ruled out.
3. **Durability rests on the kernel and on the user's storage.** An error a previous fsync (another process's, or a run before a restart) already consumed, or one lost when an inode with failed writeback was evicted, is not reported to a fresh descriptor; poisoning covers only errors this daemon saw in this run. The base is not a layer and is not synced (§1.1): the user keeps it durable, and since the gates compare metadata only, a lost base write whose metadata survived need not be refused. A retained attempt survives a reboot only if the state directory, the bundle cache and every lower are on persistent filesystems; `$XDG_RUNTIME_DIR`, which the docs suggest for short socket paths (`docs/sandbox.md:2673-2675`), and often `/tmp` are tmpfs (sweep 2 Codex N3). A bundle lower is recorded in a retained attempt's prefix by its cache path under `$XDG_CACHE_HOME` (`overlay_pack.rs:1812-1817`; the child records the canonical path, `lower_stack.rs:173-175`), which is disposable by definition: a cache cleaner that purges it leaves the retained layer without its prefix. The docs say to keep those entries while the attempt is retained, or to retain over sealed directory lowers made with `overlay unpack` (run 1 skeptic sweep 6 N3). Documented.
4. **Finalize hashes a TAR base in the serve loop.** Worker tops record `pending` and no writable index, so seal hashes the whole archive uncached under the top's root flock (digest caching is cut); Git bases do not hash. Timed in the PR.
5. **`Detaching`** is what a finalize gets while a container still runs: `docker run -v` gives the container its own copy of the mount, so the daemon's own unmount removes the host mount and the child keeps serving the container (sweep 1 Claude N3). The attempt's host path is then gone for the harness; the container's later writes still reach the overlay through the child and are sealed by the retry after the container stops; `destroy` is the other way out. This departs from "leave the attempt mounted" (source `:114`) because a non-lazy unmount that succeeds cannot be undone; the docs say to finalize only after the container stopped.
6. **Older fillers** (a ratarmount older than R1c-1 using the same cache) publish without the entry lock; a hit then waits for nothing, and its publication check refuses a root left writable (run 2 sweep 4 Codex B1), so a hit racing an old filler between its rename and its restore may refuse once; a retry after the restore succeeds.
7. **Shared cache contention.** A hit holds the entry lock shared through its verification, and S holds it exclusively through its fsyncs. A finalize (S) whose cache entry is being verified by a hit of another daemon or CLI mount waits up to `FINALIZE_WAIT` and then answers `in_use`; a child whose hit waits behind another daemon's S can reach the batch `--timeout`. Both are retryable; documented with the cache notes.
8. **The engine extraction touches R1a's landed code.** It changes no rule or byte, R1a's tests run unchanged, and `policy.py` re-reviews the moved sites in the same commit.
9. **Downgrade.** An R1a or R1b daemon refuses a `requests.jsonl` with `v: 2` finalize lines (fail closed, as R1a's plan intends for a later line schema) and cannot remove a sealed tree in `attempts/`; documented order in §5.12.
10. **Departures from the source doc**, each for a ruling, a Keystone point, the scope rule or a code fact: retained attempts do not count toward `--max-attempts` (Keystone #1); retained state is `retained.jsonl` and the directory, not `state.json`; `--max-retained` is capped at 4,096 (its default; the source names only the default); the child-exit wait is `FINALIZE_WAIT`, not the whole `--timeout`; `retain` is refused with `tmpfs` and on bases outside §5.5; a gate refusal is `io`; `erofs_denied` may be `null`; branching through the supervisor works over TAR and Git bases only; every finalize, not only a retained one, pays the sync (ruling 1+2); finalize and retain are Linux only (ruling 7); a retained attempt is listed only by v2 `list {all: true}`, where the source has `list` report `"retained"` (`source-plan-doc.md:120`), so v1 and v2 `list` keep R1a's equality (run 2 sweep 1 Claude N11); finalize syncs only on the allowlisted filesystems (§5.5).
11. **R1a's retry window bounds ruling 5 only after the target is gone** (approval note (a)). A finalize record is pinned while its target attempt exists, so a retry within the attempt's life always reaches its stored target. Once the attempt is destroyed or discarded by a restart, its records are evictable again after 65,536 newer records or 64 MiB, and a retry of an evicted request ID runs as a new request that resolves `id` again (`docs/sandbox.md:2440-2442`); if the ID was drawn again for another attempt meanwhile, that attempt is finalized. Attempt IDs carry 6 random characters from 62, so that needs the destroy, the eviction and a redraw collision. The pin's cost is the other side: every request ID used against a live or retained attempt stays in the log, so a client that sends many finalize request IDs against one attempt fills the record cap and then gets `capacity` (fail closed) until it destroys the attempt, and a retained attempt's records stay until R1c-2's `forget`. Documented.
12. **Trees must lie on one allowlisted filesystem** (ruling 6; run 2 sweep 1 Codex B1). A lower, attempt tree or index directory with a mount or a bind-mounted file inside reports devices its root does not, and is refused, before the stop; a btrfs subvolume nested in a user's directory lower has its own device but no mount entry, so it is refused only by S, after the top was sealed (documented; run 2 sweep 5 Claude N3). Every tree and directory S syncs must also be on ext2/3/4, xfs, btrfs or tmpfs; read-only images (squashfs, erofs, iso9660) are refused, because the image file behind a loop device is never synced (run 2 sweep 4 Codex B2), so a layer shipped as such an image is used as a lower through an unpacked copy. Overlayfs is refused even with uniform devices (Docker's `overlay2` root filesystem included), because its `fsync` skips lower-only files and does nothing on a `volatile` mount; FUSE, network and other local filesystems are refused as untested (§3). So must the directory each tree sits in, since finalize syncs it (ruling 1+2): a lower mounted as its own volume (`-v /srv/layers/A:/layers/A`) inside a container with an overlayfs root is refused, and the remedy is a volume one level up (`-v /srv/layers:/layers`; run 2 sweep 2 Claude B1). A supervisor inside a container therefore keeps its state directory, bundle cache and lowers on a volume mounted at or above the directories holding them; the docs say so, and the refusal names the path and its type before anything stops (at `new` with `retain`, and at finalize).
13. **The busy classification reads the helper's message.** `Mounter::stop` decides `Busy` from the CLI helper's last stderr line, a format `ratarmount-fuse` owns (`lib.rs:4139-4151`). The classifier lives beside that format, and T5b's two tests pin the pair, so changing the message fails a test rather than a harness. Not classifying would report a missing `fusermount3` as `writers_active` forever.
