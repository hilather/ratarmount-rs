## 1. Goal

Let one supervisor `new` mount `base + sealed lowers + writable top`, with an optional per-attempt operation journal, and refuse a stack whose layers record a different lower prefix or a different base identity.

1. A v2 `new` takes `lowers` (sealed layer directories or bundles, bottom first) and `journal`.
2. Every lower is checked before any directory or child exists. Each lower's recorded lower prefix must equal the lowers requested beneath it, for directories and bundles alike. A bundle sealed over layer A is never accepted without A (old blocker 2).
3. The window between validation and the mount is closed by **re-checking once mounted**: before `new` returns, every child reports the layers it took, and the metadata of what it composed is read again; both must equal what was validated (Keystone #3).
4. `diff` of a layered attempt is rendered against `base + lowers`, not the bare base.
5. Version 1 stays byte-for-byte unchanged (R1a's golden, U1).

## 5. Design

### 5.1 Protocol (D1)

- `OperationV2::New` gains:
  - `lowers: Vec<String>`, `#[serde(default, skip_serializing_if = "Vec::is_empty")]`. `null` is refused (a `Vec` rejects it).
  - `journal: Option<JournalSpec>`, `#[serde(default, skip_serializing_if = "Option::is_none", deserialize_with = …)]`, with the same helper pattern as R1a's `request_id`, so `"journal": null` is `invalid_request`, not "no journal".
- `JournalSpec` (`deny_unknown_fields`): `exclude: Vec<String>` (default `[]`, the `--journal-exclude` syntax), `reads: JournalReads` (`all` | `first`, default `all`), `sync: bool` (default false). All three are always serialized, so `Some({})` never hashes like `None` (R1a §5.4).
- v1 `Operation` is untouched: a v1 `new` with `lowers` or `journal` stays `invalid_request` with serde's text (R1a's U1).
- R1a §5.1's rule "a v2 `new` without `request_id` is a v1 `new`" becomes "without `request_id`, `lowers` or `journal`". With `request_id`, the request goes through R1a's layer, whose call into `new_attempts` now also passes `lowers` and `journal`; nothing else in the layer changes. Its outcome table already classifies R1b's outcomes by what is left: validation refusals happen before any attempt (`retryable`); `lower_changed` after a complete rollback is `retryable`, and with kept attempts it is `failed`.
- New error code `lower_changed`, reachable only from a v2 `new` with lowers.

### 5.2 Lower validation before anything exists (D2)

`lowers::validate` runs in `new_attempts` after the capacity and glob checks and before `ram_root()`, so a refusal creates no RAM state, no attempt directory and no child. Every refusal is `invalid_request` naming the path.

1. **Base rule** (scope): with non-empty `lowers`, the base must have no `binds`, must not be `recursive`, and its source must be an absolute path or a `git:///` URL (row 16).
2. **List rule:** at most 32 lowers. Each string is non-empty, NUL-free and absolute (checked before `canonicalize`, so a relative path never resolves against the daemon's cwd).
3. **Place rule,** applied twice. First lexically to the absolute input, before `canonicalize`: a path under the state root or the RAM root is refused without resolving it. A path under `attempts/ID/mnt` would otherwise be resolved through that child's FUSE mount (`daemon.rs:660`), and a stuck child would stall the serve loop. Then `fs::canonicalize` must succeed and give UTF-8, and the canonical path must be neither inside nor an ancestor of either root, which catches symlinks resolving there. That covers `attempts/` (a live attempt's top is never a lower). The RAM root is checked only once known: on a first tmpfs request it does not exist yet, so nothing can be inside it. R1c relaxes the rule for `retained/`.
4. **Type rule:** `symlink_metadata` of the canonical path is a directory or a regular file, nothing else. This runs before any open, because `File::open` of a FIFO would block the serve loop (row 8).
5. **Directory lower:** `OverlayMeta::read_no_recovery` must return `Some(meta)` with `layer_sealed()` and a `layer_digest` that passes `overlay_pack::valid_digest` (made `pub(crate)`, `overlay_pack.rs:527-535`), the check `bundle_meta` already applies to bundles. Seal always hashes with SHA-256 (`overlay_seal.rs:224-229`; the default `Algorithm`, `overlay_changes.rs:56-61`), so no valid layer fails it. Any error refuses: a hot journal, a busy database, a lost record. Never `OverlayMeta::read`, which could roll back someone else's overlay before refusing it (row 9).
6. **Bundle lower:** `overlay_pack::bundle_meta` (made `pub(crate)`) under `Limits::resolve(None, None)`. It refuses an unsealed layer or a missing digest. The full verification, against the view beneath the bundle, stays in the child, as for `sandbox run` and plain mounts (row 7). A bundle that fails it gives `mount_failed` with the mount-log excerpt, after the batch is rolled back.
7. **Snapshot** per lower: kind, canonical path and the whole metadata map (a directory's `meta` rows; a bundle's `meta.json`), from which come `layer_digest`, `sealed_at`, the recorded prefix (the `lower_layers` row, `[]` when absent; row 10), `base_digest`, `base_digest_kind` and the forced markers.
8. **Spawn flags:** `parse_args_from(mount_args(base, indexes, probe, &spec))` with probe paths, as `validate_base` does (row 15). This refuses a bad journal glob or a flag combination the child would reject.

The canonical path is what goes into the snapshot and the child's `--lower` argument, so the supervisor and the child name the same file.

### 5.3 Stack consistency, directories and bundles alike (D3, old blocker 2)

For the lower `L` at position `i` (0 is the bottom):

- `L`'s recorded prefix must have exactly `i` entries, and entry `j` must have the same `layer_digest` as requested lower `j`, for every `j < i`. A mismatch refuses, naming `L`, `i`, the requested digests and the recorded ones.
- Only digests are compared, never paths. A bundle position records the child's cache directory (row 5; `codex-8.md` #7), and the same layer may be given as a directory one time and as a bundle the next. A recorded empty digest (a layer sealed over an unsealed lower) can never match, because every requested lower has a valid digest (§5.2).
- **Base agreement:** every lower must record a comparable base identity, `base_digest_kind` `strong` (an archive base after seal, or a supplied digest) or `git-tree` (a Git base), and all lowers must record the same kind and `base_digest` (row 21). Equal layer digests do not imply equal bases (row 11): without this, a layer `A3` with `A`'s change rows over another archive or Git tree could carry `B` (sealed over `[A]`) onto the wrong base, because the child checks only the bottom lower (`lower_stack.rs:185-195`). With it, every lower names the bottom lower's base, which the child compares with the mounted base. A `weak` record (directory base) cannot be compared, since each layer's weak digest uses its own exclusions, and a `none` record has nothing to compare: both are refused. Sealed layers are never `pending` (row 21).
- A lower that records `stack_mismatch_forced_at` or `base_mismatch_forced_at` is refused (rows 11, 22): either marker says the recorded rows do not describe what the layer was written over.

So a bundle `B` sealed over `A` is refused alone, refused over another `A2`, refused when the prefix is reordered, and accepted over `[A]`. The same holds when `B` is a directory. For layers mounted and sealed over `A`, which is the sandbox's own flow and what the default `overlay seal` does (it composes the recorded lowers, `overlay_cmd.rs:352-365`), the check is complete. The one exception, an explicit `overlay seal --lower` list, is a seal-side limit (§5.4). The child still checks the mounted base against the bottom lower's record (`main.rs:1489-1547`). A refusal there is `mount_failed` with the child's message.

### 5.4 Keystone #3: re-check once mounted (D4)

**Choice: re-check once mounted, not holding the #240 overlay root flock.** The reasons, from the code:

1. **The lock would have to outlive `spawn`.** The child takes its lowers after `Command::spawn` returns, in `open_with` (row 6), and only later appears in mountinfo (`process.rs:201-214`). Covering that means holding the lock until every attempt is ready: up to `--timeout`, 120 s by default and at most 3600 (`mod.rs:45`).
2. **Both sides would wait without bound.** The public `SealOperation::acquire` reaches the lock, but `SealCommitGuard::acquire` spins with no deadline (row 13). The single-threaded serve loop would hang behind any seal in progress on a lower, and while the supervisor held the lock, every `overlay seal` or `unseal` of a shared prepared layer would hang for the whole batch startup.
3. **Bundles have no root to lock.** The child picks the cache directory while mounting (row 7).
4. **The flock excludes only seal, unseal and commit.** It does not stop a rename of another directory onto the path, or a payload edit made without the database.
5. **The re-check sees what the child took and composed.** It catches a reseal, a replaced directory, an A→B→A swap (`codex-8.md` #1) and a substituted bundle, including one with the same seal pair (below), and it blocks nobody.

**Mechanics.**
- After the readiness loop sees every attempt `ready` (`daemon.rs:694`) and before `new` returns, the supervisor calls `Mounter::lower_layers(attempt)` once per attempt of a layered batch.
- `ProcessMounter` implements it with the new inspection command `lower_layers`: the child replies with `overlay.meta_value("lower_layers")` (`[]` when absent), with the cap of `deleted_paths` (row 12). Each call's read and write timeouts are the smaller of 5 s and the time left before the batch deadline, so the re-check never runs past it; at the deadline the result is `timeout` and the batch is rolled back. Nothing goes through FUSE, so a stuck mount cannot hang the serve loop.
- **Per attempt, two comparisons with the snapshot:**
  1. **The child's records:** the same count; at a directory position the same path, `layer_digest` and `sealed_at`; at a bundle position the same `layer_digest` and `sealed_at` (its path is the cache directory the child resolved).
  2. **The metadata of what the child composed,** read now with `read_no_recovery`: at a directory position the directory's whole metadata map; at a bundle position the whole map of the record's cache directory. Each must equal the snapshot's map (a bundle's `meta.json`; the child already refused a layer whose database meta differs from `meta.json`, row 7).
- A difference is `lower_changed`, naming the attempt, the position and the differing values. An inspection or read failure is `mount_failed`. Either goes through the existing rollback (`daemon.rs:710-724`), so the whole batch is destroyed or its kept IDs are reported.
- `Supervisor` gains `taken_lowers: BTreeMap<String, Option<Vec<LowerLayerRecord>>>`. A layered attempt gets `None` when it is recorded, before its spawn, and `Some(records)` once its re-check passes. `destroy` removes the entry. An attempt kept by a failed rollback therefore stays marked as layered but unverified (D5). A plain attempt has no entry and makes no inspection call, so v1 behaviour and timing do not change.

**Why both comparisons** (sweep 1, Codex B1 and B2):
- **The child's two opens.** The child reads a lower's metadata (`lower_stack.rs:176-177`) and opens its rows by path a second time to compose it (`:214`). An unseal, edit and reseal between the two makes it compose the new layer while it records the old seal pair, so comparison 1 alone passes. Comparison 2 does not: unseal deletes `sealed_at` and writes `unsealed_at`, and every seal writes a fresh `sealed_at` (row 22). The directory's map at the re-check therefore differs from the snapshot unless its database file was restored from a copy, which is file-level tampering. For a bundle there is no such window: the child reads its rows and metadata from its own private, hashed copy (`overlay_pack.rs:1915`, `:1950-1962`).
- **The seal pair is not the metadata.** A forced pack keeps a layer's seal pair and replaces its base rows (row 22). A bundle swapped for such a pack after validation passes comparison 1 and the child's verification, but its cache directory's map carries other base rows and `base_mismatch_forced_at`, so comparison 2 refuses it. The base agreement of §5.3 was decided on the snapshot's map, so map equality is what keeps that verdict true for the layer actually mounted.
- The cache directory is the child's composed layer itself, content-addressed by the hash of its private copy and published once, read-only (`overlay_pack.rs:1927`, `:1963-1970`).

**Stated limits** (documented): nothing protects a lower after Ready, because the mount opens sealed lowers immutable and holds no lock on them (`docs/sandbox.md:544-545`). A payload edited behind a seal keeps its metadata; only `overlay verify` rehashes it. A rename that puts another directory at the path exactly between the child's two opens and restores the original before the re-check is not detected. A lower unsealed and left with a hot journal inside the window is rolled back by the child's own `OverlayMeta::read` before the child refuses it as unsealed; that is today's mount behaviour. Both need a same-user actor racing the spawn, outside the honest-mistake scope of every sandbox check. Finally, the stack check follows the **authoring** stack. `lower_layers` is written at creation from what the mount actually composed (`main.rs:2521`; `overlay_meta.rs:1412-1437`), which is the stack the layer's bytes were written over. An explicit `overlay seal --lower LIST` changes only how the seal rows are classified: seal writes `sealed_at`, `layer_digest` and `canonical_hash_format` and nothing about the stack (`overlay_seal.rs:534-542`; row 11). No metadata records such a list, so the supervisor cannot see it. That is a seal-correctness limit, not a stack gap; its closure is listed in §3.

### 5.5 Layered `diff` (D5)

For a layered attempt whose entry is still `None` (kept by a failed rollback, §5.4), `diff` is `diff_failed`: "lower stack of attempt ID was never verified; destroy it". For one with records, `diff` (v1 and v2) first re-reads each recorded layer with `read_no_recovery`. It must still be sealed with the recorded `layer_digest` and `sealed_at`; otherwise `diff_failed` names the layer. The pair suffices here: these are the directories the re-check already compared in full, and changing one in place means unsealing it, which removes `sealed_at` (row 22). Then `compose_stack(open_base(..).source, layers, Immutable)`, and the rest of `render_source` (live or offline) is unchanged. Nothing recovers a hot journal (`codex-7.md` #3), and bundles are not re-verified: the recorded cache directories are used, as the CLI `diff` uses the top's recorded paths (row 14). A plain attempt takes today's path, byte for byte (R1a's U1). `stats` reads only the top and does not change.

### 5.6 Journal and spawn flags (D6)

- `SpawnSpec` is passed to `Mounter::spawn` and `mount_args`. It starts as `{ quota, readonly }` (step 1); step 2 adds `lowers: &[PathBuf]` and step 4 adds `journal: Option<(&Path, &JournalSpec)>`, reaching the source doc's shape. `IR-B0115-M01`'s statement passes `spec` whole, so adding fields does not change its tokens again.
- Before `--`, `mount_args` appends `--lower P` for each canonical lower, bottom first; then `--journal P`, one `--journal-exclude G` per glob, `--journal-reads first` only for `first`, and `--journal-sync` only when set. It never adds `--allow-unsealed-lower` or `--force-stack-mismatch`. With an empty spec, the argv is identical to today's (L2).
- The journal path is always `attempts/ID/journal.jsonl`, chosen by the supervisor; the client never sends a path. It lies outside the mountpoint and the overlay for disk and tmpfs tops (row 15). It is deleted with the attempt (`destroy`, `reconcile`). Harnesses summarize it before `destroy` and mark turns with `ratarmount journal mark <attempt path> LABEL`. No new operation is needed.
- **Results keep the v1 attempt shape.** The journal location is the documented contract `<parent of path>/journal.jsonl`. The layers a mount took are on its root as `user.ratarmount.layers`. Its `user.ratarmount.stack_digest` is empty while the base digest is `pending`, which is the normal state for a prepared archive base: workers open the index read-only, and the mount's background hasher leaves the digest pending without a writable cache (`main.rs:2522`; `base_digest.rs:55-63`; `overlay_meta.rs:1425-1438`). R1c's finalize reports the stack digest after its seal. Repeating lower paths in every attempt object would grow a `count` 4096 result past the response and record caps (`codex-7.md`, result-size finding). R1a's stored-record preflight and its U2 result-equality rows therefore need no change.

### 5.7 Hashing (Keystone #4, D7)

Hashing is in R1b's scope only through the two new fields. R1a's definition is unchanged: typed `OperationV2`, top-level defaults removed, nested values hashed whole, members sorted by UTF-8 key bytes at every depth by R1a's own writer (R1a §5.4). That is Keystone #4's "canonicalize explicitly"; R1b adds no `preserve_order` assertion. With the feature off (row 20), `serde_json::Map` is a `BTreeMap`, whose order already equals UTF-8 byte order, so no test can observe the writer's own sort today. The permutation tests and two golden digests (L1) pin the observable contract; the writer's sort keeps it if a dependency ever enables the feature.

- `lowers` order changes the hash; an empty `lowers` hashes as absent.
- `journal` absent ≠ `journal: {}`; `{}` = `{"exclude":[],"reads":"all","sync":false}`; `exclude` order changes the hash.
- Lower strings are hashed as sent, not canonicalized: `/a/b` and `/a/b/` under one `request_id` are `idempotency_conflict`. Documented.

### 5.8 Lock order: the #240 correction, recorded for Keystone

> **The #240 order as the code has it. Seal takes no archive lock.** The order relayed by Keystone ("seal takes the exclusive archive lock first, then the overlay DB lock; commit re-checks `layer_sealed` under the archive lock") contradicts the code on both points.
> - **Seal** takes only the overlay **root** flock (`SealCommitGuard`, `overlay_seal.rs:409-412`; the flock at `write_overlay.rs:7424-7446`), then its database transaction (`BEGIN IMMEDIATE`, `overlay_seal.rs:456`). "Seal never acquires an archive lock" (`overlay_seal.rs:276`). It reads the archive through `SealArchive` after a stamp check (`:433-439`). Unseal takes the root flock and then its transaction (`:675-678`).
> - **Commit** takes the same root flock and re-checks `layer_sealed` under it (`OverlayCommitGuard::acquire`, `write_overlay.rs:7357-7363`; "It always acquires the overlay lock before any archive guard", `:7350`), and only then the archive flock, `LOCK_EX|LOCK_NB` (`ratarmount-compress/src/commit_journal.rs:707-717`).
> - `docs/sandbox.md:601-616` states the same order.
>
> **R1b's locks:** `daemon.lock` only. It takes no overlay root flock, no archive lock and no write transaction. Lowers are read with `read_no_recovery` (read-only, `busy_timeout(0)`) and `bundle_meta` (a streamed read). Keystone #3's lock option was judged against this real order (§5.4). Finalize's seal is R1c.

## 8. Risks

1. **Bundle cost.** Each child privately copies, hashes and verifies a bundle lower on every spawn; without a cached base digest there is no trusted marker (rows 3 and 7). With digest caching cut, `count` 64 over a 1 GB bundle copies about 64 GB through the cache, and readiness may hit `--timeout`. The docs recommend sealed directories for fleets; the PR records one timing (`skeptic-9.md` N13). Supervisor-side resolution is a follow-up (§3).
2. **The strict stack check refuses independently sealed layers.** A layer sealed over the bare base (for example a hidden-tests layer) cannot sit above other lowers in a supervisor attempt. The R5 hidden-tests recipe (R1c) adds that layer in a direct grading mount (`source-plan-doc.md:288`), which R1b leaves unchecked (§3). R1c's recipe text must not route it through the supervisor.
3. **Limits of the checks** (§5.3, §5.4): nothing after Ready; payload edits behind a seal; a layer sealed with an explicit `overlay seal --lower`; a rename timed between the child's two opens and undone before the re-check. The child's bottom-lower base check uses metadata only (an archive's size and mtime, a Git tree id), so a same-size, mtime-restored archive edit passes at mount, as `docs/sandbox.md:566-567` already says. Documented.
4. **Directory bases need a supplied digest for lowers.** Requiring a comparable base identity (§5.3) refuses layers that record a `weak` digest, which is every layer made over a directory base without `--base-digest`. The sandbox's own flow uses archive snapshots and Git bases (`docs/sandbox.md:17-51`, `:2146-2149`), whose layers record `strong` or `git-tree`. The refusal names the fix.
5. **Serial serve loop.** `meta.json` is the last bundle member (`overlay_pack.rs:469-484`), so validation decompresses each bundle lower completely, once per request, inside the serve loop, up to the `Limits` default of 32 GiB (`overlay_pack.rs:1386`). The docs state this cost, and the PR's timing (§7) measures it. The re-check adds one bounded inspection call per attempt. A bundle replaced by a FIFO between the type check and the open would block the daemon in `open(2)`; that needs a same-user adversary, which is out of scope like every sandbox check.
6. **The manifest re-review** of `IR-B0115-M01` (§5.9) is an explicit step-1 item; a missed regeneration fails `policy.py` in that commit, not later.
7. **Child messages name CLI flags** the API cannot pass (`--force-stack-mismatch`); documented with the `mount_failed` cases.
8. **Downgrade to R1a.** R1b writes no new request-log line kind, so an R1a daemon still opens the log (R1a §5.5). Its replays return stored results unchanged. A retry whose body carries `lowers` or `journal` is refused at parse (`invalid_request`, R1a §5.1) before any lookup, so it fails closed.
9. **Departures from the source doc**, all for the scope rule or a code fact:
   - the place rule covers the whole state root and RAM root, not only `attempts/`;
   - a bundle is checked structurally before spawning and verified by the child, because only the child opens the view beneath it;
   - lowers are refused on `binds`, `recursive` and non-local bases, and when they record a `weak` or `none` base identity;
   - `lower_changed` is new;
   - layers with a forced marker are refused, and every lower's `strong` or `git-tree` base identity must agree (§5.3).
