## 1. Goal

1. One `finalize_top`, shared by `sandbox run` and the supervisor. `sandbox run` reports stay byte-identical (source test 10).
2. A v2 `finalize` that stops an attempt without a lazy unmount, then fscks, seals under the overlay root flock with a deadline, hashes, optionally packs, and reports. It answers `writers_active` while writers remain, and is retry-safe under R1a's `request_id` (Keystone #6).
3. Attempts created with `retain` survive restarts in `state/retained/` until `forget` (Keystone #1, #2). None is acknowledged after the kernel reported a writeback error that may have lost its files (§5.5).
4. Restart recovery that never acknowledges a retained attempt before its rename is durable (old blocker 3).
5. The R5 notes: the journal is not model context; a hidden-tests recipe.

## 2. Scope

- `protocol.rs`: `retain` on v2 `new`; v2 `finalize {id, pack, request_id}` and `forget {id}`; the code `writers_active`; the statuses `finalizing`, `finalized`, `retained`, `retained_damaged`, `forgetting`.

## 3. Out of scope

- **R1a and R1b redesign.** R1c changes R1a and R1b code only at the extension points they name: `Kind` gains `finalize` (`requests.rs:146-151`: "R1c adds `finalize`"); the request-ID layer gains a second operation kind and its outcome classification (R1a §5.3); the reserved set gains retained and finalize IDs (R1a §5.6); R1b's place rule gains the `retained/` exception (R1b §3, §5.2). The engine extraction in §5.2 changes no R1a rule, line format or answer; R1a's tests run unchanged as the proof.
- **Digest caching** (`.digest-lock`, `overlay_base_digests`, hashing at `create_base`): cut entirely, not deferred. Finalize hashes an archive base itself (Risk 1).
- **R2–R4**, and everything in the source doc's §9 (episode graph, operation queue, cancel, artifact transfer, object store, identity profile, new crates, gateway, sampler, fault worlds, tensor export, Harbor).
- **Coverage outside the sandbox path.** `finalize` and `retain` are refused with `invalid_request` on bases with `binds`, `recursive`, or a source that is not a local absolute path or a `git:///` URL, the same base rule R1b applies to lowers (R1b §5.2 rule 1).
- **Finalize over a `git_synthetic_head` base** (Claude sweep-4 B1). Sealing over the synthetic `.git` view gives a layer no offline verb can check, since none of them builds that view (row 25); sealing over the plain view would make R1b's children, which mount with the synthetic head, fail to verify its bundle. So `finalize` and `retain` refuse such a base with `invalid_request` ("register the base without `git_synthetic_head` to finalize it"); its `new`, `diff` and `stats` work as today. Recording the view and replaying it in the offline verbs is a separate issue. The R5 recipe text says so (§5.13). No other archive formats, mount modes, HTTP/WebDAV/NFS frontends, tensors or `ratarmount_rs` bindings are covered. A reviewer request for more is recorded here, not planned.
- **Archive bases other than TAR** (Claude sweep-5 N4). `create_base` accepts any archive `prepare` can index (`process.rs:148-169`; `docs/sandbox.md:2309`). Finalize's classification, gate, seal and hash do not depend on the format, so a ZIP or ISO base goes through the same code, but only TAR is tested (T18). They are not refused: the supervisor sees a base's format only when it classifies the base, in step 6 after the stop (§5.4), and a refusal there would come after the attempt was unmounted. The prepared index's `backendName` (`ratarmount-index/src/lib.rs:2220`) would tell earlier, but reading it at `create_base` would refuse such bases for v1 `new`, `diff` and `stats` too, which the docs promise (`docs/sandbox.md:2309`). Reading it at `new` would add an index read the supervisor makes nowhere else. A request to test or refuse them is recorded here.
- **`retain` with `overlay: "tmpfs"`**: refused at `new`. The RAM overlay lives outside `attempts/ID` (`daemon.rs:834-836`), so the commit rename would not move it.
- **The namespace survivor scan** of the old plan (§6.4.1 there) and its step-0d observation list. §5.4 removes the need for it.
- **An agent's mode-000 directory.** Finalize fails on it with `io` naming the overlay (fsck and seal cannot walk it), and `destroy`/`reconcile` still fail on it as today (`daemon.rs:456`, `:908-910`): `remove_contents` must open a directory before it can `fchmod` it (`overlay_pack.rs:1180-1205`), so one non-empty such directory blocks the next start until its mode is restored (documented, with `chmod -R u+rwX`). Fixing removal of unreadable directories needs a directory twin of `host_stat::chmod_entry_at` and is a separate issue (`skeptic-9.md` N17).
- **Attempt-level `allow_globs`**: refused until Keystone assigns it (R1a §3).
- **CI wiring** for the FUSE, privileged and Python tests: hand-run and recorded in the PR, as in R1a §3 and R1b §3.
- **Request IDs on `forget`** and on any operation other than `new` and `finalize`.
- **State directories on filesystems without `RENAME_NOREPLACE`** (NFS, for example): the commit and `forget` renames fail there with `io`, and nothing is renamed (documented; no probe).
- **A base gate for `diff` of live attempts**: R1a's and R1b's behaviour, unchanged. R1c gates only the `diff` of finalized and retained attempts (§5.7).
- **Probing the child for open write handles before the unmount** (sweep-1 Claude N2's optional mitigation): it cannot close `Detaching`, since a private bind without open files still keeps the child alive.

## 5. Design

### 5.1 Protocol

- **v2 `new`** gains `retain: bool` (`#[serde(default, skip_serializing_if = "is_false")]`). R1a's `defaults()` (`requests.rs:332-342`) gains `("retain", false)`, so R1a's golden digest (`requests_tests.rs:114-117`) is unchanged. R1b §5.1's rule becomes: a v2 `new` without `request_id`, `lowers`, `journal` or `retain` is a v1 `new`. Results keep the v1 attempt shape (R1b D6), so the flag lives in a side map, `retain_requested`, kept like `taken_lowers` and removed by `destroy` and the commit.
- **`finalize {id, pack = false, request_id?}`** and **`forget {id}`**, both `deny_unknown_fields`; `request_id` uses R1a's string-only deserializer (`protocol.rs:106-112`), so `null` is refused. `defaults()` gains `("pack", false)` for `finalize`.
- **v1** is untouched: `finalize`, `forget` and `retain` stay unknown and `invalid_request` (R1a U1).
- **New codes `writers_active` and `base_changed`** (v2 only). `base_changed` is finalize's answer when the base gate refuses (the base differs from what the top recorded), so a harness can tell a refusal that a retry will not fix from a transient `io`. Existing codes keep their meaning; `lower_changed` (R1b) is reused when a recorded lower changed, and `in_use` when its database is locked.
- **Statuses.** `starting`, `ready`, `crashed` (v1); `finalizing` (finalize started and has not finished; resumable); `finalized` (done, not retained); `retained`, `retained_damaged`, `forgetting`. v2 `list` shows every attempt and every retained entry. v1 `list` keeps today's code over the `attempts` map (`daemon.rs:547-556`): after a v2 client finalizes, it also shows `finalizing` and `finalized`, including through the CLI's `sandbox list` and Python's `list()`, which send v1; it never shows retained entries. Step 3 changes the v1 `list` row of `docs/sandbox.md:2311`, which today names only `ready` and `crashed`, to say so.

### 5.2 One durable-log helper (the requirement, and the correction to its premise)

**The premise.** The request names "the ONE shared fsync/compaction helper used by requests.jsonl (R1a) and the R1b journal". Only R1a has one. R1b's journal is the child's operation journal (row 9), not a daemon log, and R1b adds none. R1c leaves `OpLog` alone (it is R1b's design); the journal is made durable before a retain by the barrier in §5.5.

**The approach: extract, never copy.** Step 1 moves R1a's record-independent machinery out of `RequestLog` into `ratarmount/src/sandbox/state_log.rs` as `StateLog<R: Records>`: the checked open, sync-before-acting, the bounded streaming replay with torn-tail truncation and damage refusal, leftover removal, append-then-`sync_data` with truncation, `Broken`, verbatim compaction with backoff, the fault points and events. `Records` supplies `parse`, `apply`, the live lines in file order, `live_bytes` and whether compaction may run. `pub type RequestLog = StateLog<RequestRecords>` keeps every name R1a's tests use (`faults`, `events`, `line_high_water`, `live_lines()`, `is_broken()`, `status()`, `descriptor()`, `requests::{Fault, Append, TEST_FAULTS, TEST_LIMITS, BEFORE_OUTCOME}`), and messages keep their text (`requests.jsonl must be …`, `request record at byte N`), so R1a's suite runs unchanged. Each log gets its own `#[cfg(test)]` fault queue and event list, so arming R1a's `TEST_FAULTS` never hits the second log, and R1a's event assertions (`requests_tests.rs:497`, `:630-640`) never see R1c's syncs; the supervisor-level events T8 checks go to a recorder of their own. The engine's directory fsync (`sync_dir`, today's `IR-E0145-M01` statement, which opens a new handle per call) serves every directory fsync R1c needs. It is never the barrier's watch, which must be older than the writes it covers (§5.5). No other fsync or compaction code is written.

**Durable state, and which log holds it.**

| State | Where | Why |
| --- | --- | --- |
| Finalize request records | `requests.jsonl`, as `v: 2` records with `op: "finalize"` | R1a's layer, its eviction window and its reservation apply unchanged. |
| Retained attempts | new `retained.jsonl`, through the same engine | Request records are evicted (65,536 records or 64 MiB, `requests.rs:928-938`); a retained attempt must never be forgotten by eviction. |
| Finalize progress (§5.3) | memory only | An unretained attempt is disposable: a restart deletes it with its progress (`daemon.rs:441-457`). Once retained, the full report is in `retained.jsonl`. |
| Recovery decisions (§5.6) | `aborted` lines in `retained.jsonl`, resolution lines in `requests.jsonl` | Recovery writes nothing else. |

**`requests.jsonl` finalize lines are a new schema, so they bump `v`** (R1a's rule, row 20; Codex sweep-2 B1). `v: 1` stays exactly R1a's schema: `op: "new"` and its members, byte for byte. `v: 2` is the finalize record: `op: "finalize"` only, with `attempts: [ID]` (one valid ID) and `pack` in every state, `result` on `done` and `error` on `failed`. A `running` line therefore names its attempt (restart resolution, §5.6) and reserves its ID while it lives (R1a §5.6):

```text
{"v":1,"id":"r1","t":"done","op":"new","op_hash":"sha256:…","attempts":["attempt-a1B2c3"],"result":[…]}
{"v":2,"id":"r9","t":"running","op":"finalize","op_hash":"sha256:…","attempts":["attempt-a1B2c3"],"pack":true}
{"v":2,"id":"r9","t":"done","op":"finalize","op_hash":"sha256:…","attempts":["attempt-a1B2c3"],"pack":true,"result":{…}}
```

`parse_line` dispatches on `v` first; a `v: 1` line with `op: "finalize"` or a `v: 2` line with `op: "new"` is a schema error. One file holds both versions in any order, replay applies them alike, and compaction copies every live line verbatim, its `v` included. Every finalize error is `retryable`: nothing finalize does needs undoing, and a retry resumes (§5.4). Only a restart writes `failed interrupted` for a finalize, with its own message ("finalize was cut off by a supervisor restart before attempt ID was retained; the attempt was discarded").

**`retained.jsonl`** (`v: 1`; 0600, owned, one link, like `requests.jsonl`):

```text
{"v":1,"id":"attempt-a1B2c3","t":"retained","base":"task","over":["attempt-z9Y8x7"],"report":{…}}
{"v":1,"id":"attempt-a1B2c3","t":"aborted"}
{"v":1,"id":"attempt-a1B2c3","t":"forgotten"}
```

`over` lists the retained entries the layer was built over (§5.7), so `forget` knows a layer's dependants without reading any database. A record is live while its last line is `retained`; `aborted` and `forgotten` end it, and compaction drops it. There is no eviction; `--max-retained` bounds the live set. The engine keeps live lines in memory (`requests.rs:377-386`), so the line bound is 16 KiB and `--max-retained` is at most 16,384: at most 256 MiB, about 12 MiB at the default 4,096 with reports of about 3 KiB. Every path in a report is short, because the state root must leave room for `attempts/ID/inspect.sock` in `sun_path` (`docs/sandbox.md:2479-2484`), and `over` holds at most 32 IDs (R1b's lower cap); finalize still refuses (`io`, before the barrier) a record over the bound. Damage before the last line of `retained.jsonl` refuses the start with its own advice (Claude sweep-3 N7), because R1a's "move it aside to start without request records" (`requests.rs:596`, `:605`) would lose more here: "moving it aside keeps every `retained/` tree but makes each `retained_damaged` without its report; dependencies are read back from each layer's database where it can be read; forget them or restore the file".

**R1a's Risk 5, decided.** A daemon older than R1c refuses to start on a `requests.jsonl` holding `v: 2` lines. Its `parse_line` checks members before `v` (row 23), so it names an unexpected member (`attempts` on a `running` line, `pack` on a `done` one), not the version; the docs quote neither text. R1c keeps that fail-closed behaviour instead of an encoding R1a could misread. Older daemons ignore `retained.jsonl` and `retained/`; both come back after an upgrade. **Downgrade** (Codex sweep-2 N4): an older daemon deletes `attempts/*` with `remove_dir_all` (`daemon.rs:456`), which fails on the sealed tree a crashed or unretained finalize leaves, so it would not start. The documented order is: start R1c once (its `reconcile` removes sealed trees, §5.8), `shutdown` it, move `requests.jsonl` aside, then start the older daemon; or restore owner write bits on the leftover attempt trees (`chmod -R u+w`) first.

### 5.3 `finalize_top` (new `ratarmount/src/sandbox/finalize.rs`)

```text
pub(crate) struct FinalizeInputs<'a> {
    top, manifest: &Path, journal: Option<(&Path, &Path /* summary */)>,
    open: &mut dyn FnMut(Option<&OverlayMeta>) -> io::Result<(ClassifiedBase, Arc<dyn MountSource>)>,
    base_digest: Option<String>, seal: Option<SealLock /* Wait; step 3 adds Until(Instant) */>,
    pack: Option<(&Path, Option<PathBuf> /* include_journal */)>,
}
pub(crate) struct FinalizeProgress { fsck_result, packed }   // filled as each phase completes
pub(crate) enum FinalizeError { Gate(io::Error), Busy(io::Error), Io(io::Error) }
pub(crate) fn finalize_top(inputs, progress: &mut FinalizeProgress) -> Result<FinalizeReport, FinalizeError>
```

`FinalizeError` only sorts errors for the supervisor (§5.4 step 6): `Gate` is a real base mismatch, `Busy` any `WouldBlock`, `Io` the rest, including a base the gate could not measure or stat (Claude sweep-3 N5). `overlay_cmd::gate_base` gains a typed twin that tells the two apart (row 23: `comparison.mismatch` against `compare_base_identity`'s own error); `gate_base` keeps its signature and text by formatting the twin's result, so its other callers do not change. `sandbox run` turns each back into the same `io::Error`, so its error text and reports do not change. A retry gets the layer digest from `finish_if_sealed`, so progress does not keep it.

Phases, in `sandbox run`'s order (row 6):

1. **fsck**: `fsck(top, repair = !sealed)`; a sealed top is checked read-only (repair is refused on it, row 5). It must be clean. `progress.fsck_result` keeps the first `repaired:N` a try reached, else this try's result; an `errors:N` from a try that then failed is never kept (Claude sweep-4 N3).
2. **Gate and seal.** With `seal`: `SealOperation::acquire` (`Wait`, today's spin) or the new `acquire_until` (`Until`; `WouldBlock` at the deadline), then `finish_if_sealed`; under the guard `OverlayMeta::read`, `open(meta)` (classify and compose), `gate_base` with `force_base_mismatch: false`, then `SealOperation::seal`, which consumes the guard. A top sealed by an earlier try is still classified and gated, as `overlay pack` gates a sealed layer (`overlay_cmd.rs:479-484`). Without `seal`: classify, compose and gate, no lock.
3. **Pack**, once (`progress.packed`), with the base still open, so a downloaded base's keep-alive lives through it (sweep-7 Codex 1).
4. **Hash and outputs**: `change_set` and `canonical_hash` with `Normalize::Strict`, the manifest and the journal summary (both overwritten), `OverlayMeta::read`, and the `FinalizeReport` (`fsck_result` from progress, `patch_hash`, `layer_digest`, `manifest_path`, `journal_summary`, `bundle`).

**Old blocker 4, fixed by an out-parameter.** `codex-9.md` #3: "`finalize_top` returns its `fsck_result` only inside a successful `Finalized` … the function returns `Err`, losing the repair result." Here every phase writes `progress` as it completes, so an `Err` from phase 2 (a lock timeout) still leaves the repair result, and the supervisor keeps `progress` on the attempt. The overlay's `fsck_result` row is no carrier: seal rewrites it (row 5).

**`sandbox run`** keeps its classification (`classify_base(Some(&args.base), …, &OverlayRunContext::default())`), its `compose` of `args.lower`, `SealLock::Wait`, `sidecar(top, …)` outputs and its `--base-digest`; it builds today's JSON from the report plus its own fields. The report builder takes the elapsed seconds as a parameter, so the golden (T1) compares bytes. Classification moves under the root flock when sealing, which is `SealOperation`'s contract (`overlay_seal.rs:335-336`) and changes no report byte. `ProgressToStderr` (`run.rs:1105`) stays in `run.rs`, around its `finalize_top` call: it redirects the whole process's fd 1 (row 21), which the daemon must not do on every finalize.

**`acquire_until(dir, deadline)`** in `ratarmount-compositing`: `SealCommitGuard`'s loop with a deadline; `acquire` becomes `acquire_until(dir, None)` and behaves as today. Its non-Unix twin goes into `overlay_seal_unsupported.rs`.

### 5.4 Supervisor `finalize`

**Order of one try** (`daemon.rs`; every step checks whether an earlier try already did it):

| # | Step | On failure |
| --- | --- | --- |

Status becomes `finalizing` once step 4 returns `Stopped` or `Detaching` (`Busy` leaves it as it was), and `finalized` (or `retained`) at the end; a failure leaves it resumable. A `finalized` attempt keeps its report in memory and its `--max-attempts` slot until `destroy`.

**Classification** (`classify_supervisor_base`): `check_offline_journal` (as `base_identity.rs:206-207`), then `ClassifiedBase::open` over `FactoryOpener::new` with the worker's parameters (row 26): typed and factory paths `[source]`, `open_base`'s `OpenOptions` (`daemon.rs:1004-1015`, factored into one function both use), `recreate` false, default `CompositingOptions` and `SourceBindings` (no `recursive`, no binds, §3), and `pin_git` true, so the recorded kind and place rows are the ones the worker wrote. **Archive preflight** (Codex sweep-4 B1): a prepared index refuses a changed archive at the factory open, before any gate (row 26), so for a top that records `base_local_path`, finalize and the gated `diff` first compare that file's size and mtime with the top's `base_size` and `base_mtime_ns`; a difference is `Gate` (`base_changed`, or `diff_failed`) without opening the factory. A refusal of the open itself (a missing or damaged index) stays `io`. The composed view is `compose_stack` over the base and the child's recorded layers, through R1b §5.5's function. So gate, seal and hash see the stack the mount took and the view `diff` renders against.

**Stop: decided by the kernel, no namespace scan (sweep-6 B1).** `ProcessMounter::stop(attempt, FINALIZE_WAIT)`:
1. If `attempt.path` is mounted (by `Mounter::mounts_below`, below): spawn `<binary> -u -- PATH`, which is `ratarmount_fuse::unmount` (non-lazy, about 1 s of busy retries), in a process group of its own (`CommandExt::process_group(0)`), and bound it at 3 s, as `detach`'s first step does (row 12; the source doc's "`Mounter::cleanup`'s first step only", `:114`). A helper still running then is killed with its whole group and reaped, so its `fusermount3` child (`lib.rs:4082-4092`) cannot unmount after `stop` has returned (Claude sweep-5 N9, Codex sweep-5 N2). The FUSE child is never signalled. Then the mount table decides: still mounted is **`Busy`** (also when the helper stalled; Codex sweep-2 N2). Nothing else changed; the status stays `ready` (or `crashed`), and the attempt stays mounted (Keystone #6).
2. Whether a child must be waited for comes from `ProcessMounter`'s child registry and kept exit statuses, never from the attempt's status: a `crashed` attempt can still have a live child (row 21). A recorded child is waited for without killing it, up to `FINALIZE_WAIT` (below; the same 10 s as `run.rs:25`). Exited, or no child recorded: **`Stopped { exit }`** (`exit` from the kept status, `None` if unknown). Still alive: **`Detaching`**: the host mount is gone, but another mount of the FUSE superblock keeps the child serving.

`Busy` and `Detaching` give `writers_active` with a diagnostic stage token (`stage=unmount`, `stage=exit`; step 6 adds `stage=seal-lock` and `stage=database`); nothing is sealed. The `stage=exit` message is neutral, because a child can also outlive `FINALIZE_WAIT` on its own (a `--journal-sync` fsync, `oplog.rs:580-583`, or a large overlay drop): "the mount process has not exited after the unmount; it may still be finishing, or another mount namespace may hold the attempt (`findmnt -N PID`, `lsns -t mnt`); retry". A retry of a `Detaching` attempt re-reads `erofs_denied` over the inspection socket (the child still serves it), then checks the child once with `try_wait`, without blocking the serve loop. `FINALIZE_WAIT = min(--timeout, 10 s)` is one named constant, also used as the seal-lock deadline (§5.3); the docs cite it in the retry advice.

`destroy` of a `finalizing` attempt, `Detaching` included, is allowed and keeps `cleanup`'s kill-and-lazy policy, as for a running attempt today. Its overlay is deleted with it, so a write cut off by the kill is discarded too; a container still holding a private copy then sees a dead mount, as it does after today's `destroy`.

Why this removes sweep-6 B1's false positive: B1 was "on systemd hosts, the step 4(a) namespace scan reports `writers_active` on every finalize" (`skeptic-6.md`), because copies of the attempt in service namespaces looked like writers. There is no scan. Those copies are propagation copies: a non-lazy unmount removes them with the host mount, or fails with `EBUSY` if one is in use, which is a real writer. A copy that propagation does not remove (a container's private bind, a private namespace) keeps the child alive, so finalize answers `writers_active` until it goes. Writes reach the overlay only through the child, so seal never runs while a FUSE writer can exist: that safety property holds whatever the kernel does with a copy. What the kernel does decides only liveness. One case rests on unobserved kernel behaviour (sweep-1 Claude N1): a copy made by a user-namespace sandbox (flatpak, toolbox, `unshare -Urm`) started while the attempt is mounted is locked to its parent. The unmount clears that lock on the copies at the unmounted place before it propagates (`propagate_mount_unlock`, the correction `codex-7.md` #10 made to the old plan), so the copy should go; if a kernel keeps it, finalize answers `writers_active` (`stage=exit`) until that sandbox exits, and `destroy` is the only other way out. F5 records which happens on the author's host. The only departure from the source doc (`:114`, "leave the attempt mounted") is `Detaching`, where the host mount is already gone; the alternative is a scanner whose kernel premises were never observed (`skeptic-9.md`, "pending step 0d"). Keystone signs off Risk 3 before step 3 starts.

**Around the stop.** `supervise()` polls only `starting` and `ready`. `ProcessMounter` keeps each reaped child's `ExitStatus` (from `poll` and `stop`). **`Mounter::mounts_below(path)`** answers which mounts sit at or below a path: `ProcessMounter` reads `process::mountpoints()` (with a `#[cfg(test)]` table override for its own unit tests), and the Fake answers from its mount map, so every mount check in R1c (the stop, the removal wrapper, `forget`) runs in unprivileged unit tests (both sweep-2 skeptics). `deleted_paths` keeps today's rule for v1 statuses (`process.rs:216-223`: offline only for `crashed`); a `finalizing` or `finalized` attempt uses the inspection socket only while its child is alive (`Detaching`), and the offline database otherwise. **`erofs_denied`**: `inspection::start` also takes the quota handle (`main.rs:2641`), and a `status` command answers its `status_text()`, parsed by `run.rs`'s `parse_erofs_denied`. Like `deleted_paths`, `status` first upgrades the overlay (`inspection.rs:97-99`), so a dropped overlay ends the connection without an answer (Claude sweep-5 N6); with no policy it reports 0; with no live child it is `null`. The last value read before the child exits is kept (`codex-9.md` #6).

**Report** (source doc `:118`): `status`, `attempt` (`{id, base, path, overlay_dir, status}` with final paths), `patch_hash` (as `sandbox run`), `layer_digest`, `stack_digest` and `base_digest_state` (copied from `patch_hash`), `fsck_result`, `bytes_written`, `erofs_denied`, `manifest_path`, `journal_summary`, `journal_complete` (`true` only for a journal with a known exit status 0, `null` without a journal), `bundle`. The last two are supervisor-only (skeptic-9 N11). A retained report names `retained/ID/...` paths.

**Request IDs (Keystone #6).** The same ID and body re-run until `done`; a `done` record replays its report byte for byte without touching the attempt; another body (for example `pack` flipped) is `idempotency_conflict` in every state. Without an ID, the fast path makes a repeated finalize safe as well.

### 5.5 Retain: the commit (Keystone #2)

`new` with `retain: true` is refused (`invalid_request`) for `tmpfs`, for bases outside the §3 rule, and on a kernel below Linux 5.8 (below). It is refused with `io` while `retained.jsonl` is `Broken`, since its commit could never be recorded (Claude sweep-5 N7). It is `capacity` unless `retained (all entries) + live attempts with retain + count ≤ --max-retained` (Keystone #1: never counted against `--max-attempts`, never refused at finalize). R1–R5 run after step 6 of §5.4, so only after step 4 returned `Stopped`: `attempts/ID/mnt` is no longer a mount point and the child has exited when the attempt root moves.

| # | Step | On failure |
| --- | --- | --- |
| R1 | **Barrier**: refused at once if the writeback latch marked the attempt (below); else `Mounter::sync_filesystem` once, on the state filesystem's watch (below). It flushes everything the attempt wrote: the payload the child wrote, the database, manifest, summary, journal and bundle. Seal syncs only its sentinel (`overlay_seal.rs:550`, `:608`). The barrier does not `fsync` each file: that would open payload and database descriptors, which the #148/#151 rules avoid. `ProcessMounter` calls `overlay_pack::sync_filesystem`: `syncfs` on Linux, nothing elsewhere, since the daemon serves only on Linux (`daemon.rs:1087-1092`). The Fake can fail it | `io`, status `finalizing`, nothing renamed, no record; an error from `syncfs` also sets the latch's marks |
| R2 | Append the `retained` record: its report names the final paths, and `over` is the attempt's `retained_over` set (§5.7) | truncated, else `retained.jsonl` is `Broken`; `io` |
| R3 | `rename_no_replace(attempts/ID → retained/ID)`: `renameat_with(NOREPLACE)` on absolute paths. On success the entry leaves `attempts` and R1b's `taken_lowers` at once and enters the `retained` map as `committing`, so memory names where the tree is | append `aborted`; `io`, status `finalizing` |
| R4 | `Mounter::sync_filesystem` again, on the same watch. It forces the journal commit that makes the rename durable and reports through the same long-lived descriptor, which two `sync_dir`s on new descriptors could not (Codex sweep-5 B1). The entry becomes `retained` | the entry stays `committing` and the latch marks it (below); `io` |
| R5 | The request outcome `done` | R1a's `Broken` rules |

**Writeback errors** (Codex sweep-5 B1). A `syncfs` that returns 0 proves nothing about a page whose writeback already failed. The kernel no longer writes that page, and it reports the error once per descriptor, counting from when that descriptor was opened (row 28). So:
- **The watch** is `daemon.lock`'s descriptor. `Supervisor::open` opens it before anything else and holds it for the daemon's life, so it is older than every write an attempt makes. The supervisor keeps it as the write-only field `_lock` (`daemon.rs:400`); R1 and R4 borrow that `File`'s descriptor and never reopen `daemon.lock`, which would start a new cursor. §5.6 requires `attempts/`, `retained/` and the watch to share one `st_dev`. The barrier opens no descriptor of its own, because a descriptor opened at the barrier would miss an error that another `syncfs` caller had already seen.
- **The latch.** An error from either `syncfs` (R1 or R4) marks every attempt then in `attempts` and every `committing` entry. Marks are never cleared while the daemon runs. Since an error is observed no earlier than it happened, every attempt whose files it may cover is marked.
  - A marked attempt is never retained. R1 answers `io` before R2, with nothing renamed or recorded, under any request ID or none, even after `syncfs` returns 0 again: "a writeback error (EIO) was reported on the state filesystem after attempt ID started; its files may not be on disk, so it cannot be retained; destroy it and run it again".
  - A `committing` entry gets `io` naming the latch from `finalize` until a restart, with the advice to restart the daemon or `forget` it. `forget` still discards it (F1–F4), since discarding acknowledges nothing.
  - An attempt spawned after the error is unmarked and is judged by its own barrier, which sees any later error.
  - A refusal before `syncfs` runs marks nothing: the record bound, or a `#[cfg(test)]` fault before the call.
  - Marks are not persisted. A restart discards every unretained attempt (§5.6), and the next watch counts errors from its own open.
- **Bundle caches are synced by their filler.** A cache is shared by every later attempt over the same bundle. After a failed writeback it is still served from memory, so no per-attempt latch can protect the attempts that reuse it.
  - `overlay_pack::cached_lower_in` therefore calls `sync_filesystem` on the private copy's descriptor, after `finalize_stage` and before `publish_layer`. That copy is created in the cache before the extraction and stays open across it (row 28). An error publishes nothing and fails the mount.
  - A published cache was on disk before it appeared. A cache whose publication was lost is absent, and the next fill extracts it again (row 22).
  - This replaces sweep 3's barrier over the cache's device: the barrier now covers only the state filesystem. The base and the user's own prepared layers remain the user's to keep durable (§5.13).
- **Kernels below 5.8** never report writeback errors to `syncfs` (row 28). `Supervisor::open` parses the release from `uname`, and on such a kernel `new` refuses `retain` ("retaining needs Linux 5.8 or later"). A backported fix is not detected.

**The single commit point** is the rename made durable by R4. The record is durable before it (R2), the content before that (R1). A crash before the rename leaves `attempts/ID`, which `reconcile` deletes; the request reports `interrupted` (Keystone #2). After a power loss between R3 and R4 the rename either survived or did not; both are consistent, because the content and the record were already durable (§5.6 decides by where the directory is). A stray `retained/ID` fails R3 with `EEXIST`; nothing is replaced. If appending `aborted` then fails too, the engine truncates it or goes `Broken` (R1a's rule), and the record stays `retained` while the tree stays at `attempts/ID`: a retry writes a new `retained` line, and otherwise §5.6's third row aborts it at the next start. Until `aborted` is durable, `destroy {id}` first appends it and refuses (`io`) if it cannot, so it never deletes a tree a live record names, which a restart would list as `retained_damaged` (Claude sweep-3 N12).

**Old blocker 3, in-process half** (`codex-9.md` #2: "Track pending durability before the retained-report fast path, including calls with a different or missing request ID"). After R3 succeeds and R4 fails, the entry is `committing` and marked by the latch. It is listed as `finalizing` and refused as a lower. `finalize` under any request ID or none answers `io`, naming the latch, instead of repeating R4: a repeated sync that returns 0 proves nothing (Codex sweep-5 B1). A restart's recovery syncs both directories again and decides by where the tree is (§5.6). `destroy {id}` of a `committing` entry is `invalid_request` ("restart the daemon, or forget it").

### 5.6 Restart recovery

**Strategy: the durable rename decides; recovery completes durability, then redoes or discards.** Recovery never re-adopts a mount, never deletes a `retained/` entry it cannot account for, and acknowledges nothing until the directory entries it acts on are synced. Rolling forward an unrenamed attempt is excluded by Keystone #2.

In `Supervisor::open`, after `RequestLog::open` (`daemon.rs:387`) and before `reconcile`:
1. `private_dir(retained/)`; the state directory is fsynced when it was just created. `retained/`, `attempts/` and the held `daemon.lock` descriptor (`fstat`) must have one `st_dev`, else the start is refused, because the barrier's watch must cover the attempt trees (§5.5). Every `retained/` entry must pass `validate_name` and `private_dir`, as `reconcile` requires of `attempts/` entries (`daemon.rs:443-450`); an invalid name, a non-directory or a symlink refuses the start before anything is written.
2. `retained.jsonl` opens through the engine: checked open, file and directory sync, replay.
3. **`sync_dir(retained/)` and `sync_dir(attempts/)`, before anything is acted on** (old blocker 3, restart half: "complete the relevant directory durability operations during recovery before acknowledging retained finalizes or accepting log appends"). A visible but unsynced rename becomes durable here.
4. Match records with directories:

| Record | `retained/ID` | `attempts/ID` | Result |
| --- | --- | --- | --- |
| `retained` | present, sealed, same `layer_digest` (`read_no_recovery`), and `lower_layers()` parses (row 26; Codex sweep-4 B3) | – | `retained` |
| `retained` | present, otherwise | – | `retained_damaged`, never deleted |
| `retained` | absent | present | the rename never happened, or a `forget` renamed it back: append `aborted`; `reconcile` deletes `attempts/ID` |
| `retained` | absent | absent | `retained_damaged` (record kept) |
| none | present | – | `retained_damaged` (base `""`), never deleted. When `read_no_recovery` can read its `lower_layers()` row, its dependencies are the entries that a recorded layer's path names (`retained/<A>/…`), or whose own `layer_digest` the row records. The digest match also finds a layer used through its bundle's cache, whose recorded path is the cache directory (Claude sweep-5 N1). Otherwise its dependencies are unknown (§5.7) |

5. `reconcile` runs, deleting through `remove_tree` (§5.8); it never enters `retained/`.
6. `resolve_interrupted` resolves a `running` finalize record whose attempt is `retained` to `done` when the body is satisfied (`pack: false`, or a report with a bundle): the `done` line's `result` is the `retained.jsonl` record's `report`, byte for byte, since the answer the killed daemon was building died with it. Everything else resolves to `failed interrupted` with the finalize message (naming the attempt when damaged). Each resolution of a finalize record is a `v: 2` line with that record's `attempts: [ID]` and `pack`, so the in-memory record keeps its line's `v` and `pack` besides R1a's `attempts` (`requests.rs:377-386`); R1a's resolution writes `v: 1` with `attempts: []` (`:828-837`) and keeps doing so for `new` records.

Every refusal and every append above comes before `reconcile`, as R1a's open does (`daemon.rs:386`).

### 5.7 Retained lifecycle

- **`list`** (v2): attempts and retained entries in ID order, five keys each; a retained entry's paths are `retained/ID/mnt` and `retained/ID/overlay`.
- **`diff`, `stats`** (v1 and v2) find IDs in `attempts`, then `retained`. A finalized or retained attempt is read offline; a layered one composes its recorded layers (R1b §5.5), for a retained one read from its own `lower_layers` row. A retained layer can outlive its base by days, so before rendering, `diff` of a finalized or retained attempt classifies the base (`classify_supervisor_base`) and runs `gate_base` with `force_base_mismatch: false`, which writes nothing; a refusal is `diff_failed` with the gate's message (sweep-1 Claude N6; the CLI `diff` gates too, `diff.rs:383-389`). `retained_damaged`, `committing` and `forgetting` are `invalid_request`.
- **`destroy`** and **`shutdown`** (and `serve`'s final `destroy_all`, `daemon.rs:1155`) iterate `attempts` only, so retained entries stay; `destroy {id}` of a retained ID is `invalid_request` ("attempt is retained; use forget"). `finalizing` and `finalized` attempts are disposable and destroyed.
- **Dependencies, recorded, never read back** (Codex sweep-3 B2; Claude sweep-3 N10). When R1b's place rule accepts a `<state>/retained/<A>/…` lower for a `new` (below), R1c adds `A` to the batch's set, and each attempt of the batch gets it as `retained_over` when R1b records its `taken_lowers` entry, before any spawn (`r1b-impl` `daemon.rs:956`, row 19). So the set is known for unverified attempts too, which replaces sweep 1's refuse-everything rule. The commit copies it into the record's `over` (§5.2); recovery and `forget` read only that, so a damaged database (row 22) loses no dependency.
- **`forget {id}`** (retained, damaged, committing or forgetting entries, after `validate_name`; else `not_found`, or `invalid_request` for an attempt in `attempts`). **Refused with `in_use`**, naming the holder, while any of these holds:
  - an attempt's `retained_over` contains `ID` (live, crashed, finalizing, finalized or unverified alike; `destroy` clears it);
  - another retained entry's dependencies contain `ID`: its record's `over`, or, for an entry without a record (the log moved aside, §5.2), what §5.6 read back from its database;
  - `ID`'s own dependencies are known (it has a record, or §5.6 read them back), and some entry's dependencies are unknown (no record and no readable `lower_layers` row): that entry might depend on `ID` (Claude sweep-5 N2). Entries with unknown dependencies never block one another, so forgetting all of them first, which is the recovery the damage advice gives, cannot deadlock (Codex sweep-4 B2, Claude sweep-4 N1);
  - `Mounter::mounts_below` lists a mount at or below `retained/ID` (sweep-1 Claude N3).

  **Steps, keyed on where the tree is** (sweep-1 Codex B3):
  - tree at `retained/ID`: F1 rename it back to `attempts/ID` (no-replace), F2 both `sync_dir`s, F3 append `forgotten` (only for a recorded entry), F4 `remove_tree(attempts/ID)`. F2 keeps `sync_dir` on new descriptors: if a power loss undoes a rename-back that F2 wrongly reported durable, the restart lists a `retained_damaged` entry, and `forget` clears it again;
  - tree already at `attempts/ID` (a `forgetting` entry after F1): F2, F3 if not yet written, F4;
  - no tree (a damaged record whose directory is gone, §5.6): F3 only, which frees its `--max-retained` slot.

  A failure after F1 leaves `forgetting`, and a retried `forget` resumes. After a crash, §5.6's third row or the dead record lets `reconcile` delete the tree, so a client whose `forget` was cut off gets `not_found` on retry, meaning already forgotten (documented). Grading mounts that use the layer must be unmounted first; an idle mount elsewhere holds no descriptor, so this is a documented rule, not a check (`codex-8.md` #8).
- **As a lower** (R1b §3): R1b's place rule (§5.2 rule 3) accepts exactly `<state>/retained/<ID>/overlay` and `<state>/retained/<ID>/bundle.tar.zst` of a `retained` entry, lexically and after `canonicalize` (no symlink), and refuses everything else under the state root. R1b's checks then apply unchanged: the digest-only stack check and base agreement (R1b §5.3) cover a retained layer's or bundle's base association, the retained half of `codex-9.md` #1. Because R1b refuses `weak` identities, a layer retained over a **directory** base (workers record `Compute`, so `weak`, `process.rs:78-109`) can never be a supervisor lower; only archive and Git bases branch (documented; Claude sweep-3 N3). A recorded bundle cache that later disappears (an operator clears `~/.cache`) makes `diff` of that retained attempt `diff_failed` naming it, while a new attempt over `[bundle, retained/ID/overlay]` re-extracts the bundle (row 22).
- **Reserved IDs**: the redraw check (`daemon.rs:816`) also refuses IDs in the `retained` map, which holds `retained`, `committing`, `retained_damaged` and `forgetting` entries until their tree is gone; R1a's reserved set covers finalize lines' `attempts` while those records live, so a replayed finalize never names a redrawn ID. A tree left in `attempts/` by a failed F4 is also avoided by `tempfile` itself. The reviewed `tempdir_in` statement (`IR-B0112-M01`, `:804-812`) is not touched.

### 5.8 Removal of sealed trees

`overlay_pack::remove_tree(path)`: the module's existing `open_root` (row 23, `IR-B0046-M01`), the existing descriptor-only `remove_contents` (row 11, unchanged), and `remove_dir` of the root, whose error reports anything left. The supervisor's one deletion helper in `daemon.rs` takes **every tree an attempt owns at once** (the attempt root, and a RAM `overlay_dir` that lives outside it), first refuses (`in_use`, naming the mount, deleting nothing) when `Mounter::mounts_below` lists anything at or below any of them, because `remove_contents`' opens cross into a mount (row 21), and only then deletes (Codex sweep-3 B3). A disk attempt is removed by one `remove_tree` of its root, `overlay/` inside it; today's separate removal of `overlay_dir` first (`daemon.rs:907-909`) goes. `destroy` and `reconcile` still unmount `mnt` first (`daemon.rs:455`, `:906`). The helper replaces `remove_dir_all` in `reconcile`'s two loops, `destroy` and `forget`, so a crash between seal and rename cannot block the next start, and a sealed RAM overlay (`ram/ID` is the overlay root) is removable. v1 users also see one change: a mount left inside an attempt's tree now refuses the start, naming the mount, where `remove_dir_all` used to delete through it. ### 5.9 Lock order (re-verified on `cf8f626`)

1. **`daemon.lock`**, held for the daemon's life (`daemon.rs:336`): serializes every request, both logs, and every change under `attempts/` and `retained/`.
2. **The top's overlay root flock**: `SealOperation::acquire_until` (finalize step 6 only), released when `SealOperation::seal` returns (`overlay_seal.rs:358-364`) or when `finish_if_sealed` reports an earlier seal.
3. **Seal's database transaction**: `BEGIN IMMEDIATE` (`overlay_seal.rs:456`).

That is `docs/sandbox.md:601-620` ("The order is always overlay lock, then the existing archive guard"; seal "never acquires the archive guard", `:614-616`) and `overlay_seal.rs:275-276`. Not taken: the archive flock (commit only, `commit_journal.rs:707-717`, unreachable under `--no-recreate-index`, row 3) and the index `HashGuard` (row 4). fsck's `BEGIN EXCLUSIVE` (`overlay_fsck.rs:193`) ends at its `COMMIT` (`:208`), before step 2. R1c never holds two root flocks and never locks a lower: lowers are only read (`read_no_recovery`). `forget`, `reconcile` and `destroy` take no overlay lock.

## 8. Risks

1. **Finalize hashes an archive base in the serve loop.** Worker tops record `pending` with no writable index, so seal hashes the whole archive, uncached and under the top's root flock (row 4); with digest caching cut, every finalize of an archive base pays one full read. Git bases do not hash. Documented; timed in the PR.
2. **`syncfs` flushes whole filesystems**: the state directory's twice per retained finalize (R1 and R4), and the cache's once per new bundle-cache fill, in the child (§5.5). It costs most while other attempts are writing. Needed for power-loss durability (§5.5); the PR times it while eight other attempts write.
3. **`Detaching`** answers `writers_active` after the host mount is gone, not "leaving the attempt mounted" (Keystone #6; source doc `:114`), for writers outside mount propagation. The harness stops its container and retries; it must not use `attempt.path` in between. If a kernel keeps a user-namespace sandbox's locked copy (§5.4), `writers_active` lasts until that unrelated sandbox exits, and `destroy` is the other way out; F5 records the host's behaviour. Keystone signs this off before step 3 starts (step 3 is about half the work); the alternative is the namespace scan R1c drops (§5.4).
4. **The engine extraction touches R1a's landed code.** Mitigated: it changes no rule or byte, R1a's tests run unchanged, and `policy.py` re-reviews the moved sites in the same commit.
5. **Downgrade.** A daemon older than R1c refuses a `requests.jsonl` with `v: 2` lines, and cannot delete a sealed attempt tree (§5.2). Documented order: start and `shutdown` R1c once, move `requests.jsonl` aside, then start the older daemon.
6. **Startup cost**: up to `--max-retained` `read_no_recovery` opens and two directory fsyncs before serving; timed in the PR.
7. **Same-user actors** are outside every sandbox check: editing a sealed layer behind its seal, placing entries in `state/`, or swapping directories during removal.
8. **Departures from the source doc**, each for a Keystone point, the scope rule or a code fact: retained attempts do not count toward `--max-attempts` (Keystone #1); `retain` with `tmpfs` refused; finalize and `retain` refused outside the §3 base rule; `Detaching`; `journal_complete`; `erofs_denied` may be `null`; `forget` takes no `request_id`; retained state is `retained.jsonl` plus the directory, not `state.json`; `--max-retained` is capped at 16,384 (§5.2); `retain` is refused below Linux 5.8 and never acknowledged after a writeback error that may cover the attempt (§5.5); the child-exit wait is `FINALIZE_WAIT = min(--timeout, 10 s)`, not the whole `--timeout` (`:114`); a gate refusal answers the new `base_changed`; branching through the supervisor (source doc Non-goals, `:66`) works over archive and Git bases only, because a layer over a directory base records `weak` and R1b refuses it as a lower (§5.7). One change deliberately reaches outside the supervisor: `cached_lower_in` serves every `--lower` bundle mount, CLI mounts included, and every first extraction now waits for one `syncfs` of the cache's filesystem (§5.5). Limiting it to supervisor workers would leave the gap, because a cache filled without a sync by any caller can later be reused by a retained attempt.
9. **How long one finalize blocks the serial daemon** (Claude sweep-3 N11, Codex sweep-3 N6). Its waits are each bounded: the inspection `status` read up to 5 s (`inspection.rs:126-127`), the unmount helper 3 s, the child-exit wait `FINALIZE_WAIT`, the seal lock `FINALIZE_WAIT`. Hashing the base (Risk 1), packing and `syncfs` (Risk 2) are not bounded, so a whole finalize is not bounded by `FINALIZE_WAIT`; a `Detaching` retry adds no wait (§5.4). Documented with the retry advice.
10. **`forget` after a lost record**: an entry with no record and no readable database has unknown dependencies, so `forget` of a recorded entry answers `in_use` until that entry is forgotten; unknown entries never block each other (§5.7). Everything R1c makes has its dependencies recorded. Read-back matches by path and `layer_digest`, so an entry whose own database is unreadable cannot be matched by digest: a layer built over its bundle loses that protection (Claude sweep-5 N1).
11. **Budget** (Claude sweep-4 N6; `skeptic-9.md` N17): R1c is about 10 days against the source doc's 3 plus 1–2 for this slice (`:156`); with R1b, R1 comes to about twice the doc's 8–10 days. Keystone signs off the budget before step 1.
12. **Durability rests on the kernel and the filesystem** (Codex sweep-5 B1, N4).
    - The latch needs `syncfs` to report writeback errors (Linux 5.8). Older kernels are refused, and a backport is not detected.
    - In-process, R1 and R4 sync through the watch. Recovery's `sync_dir` (§5.6 step 3) uses new descriptors, because no older one exists at a restart. `forget`'s F2 does too, since a lost rename-back only leaves a `retained_damaged` entry (§5.7). On a journaling filesystem a failed metadata commit makes every later write fail, so the restart refuses to start. On a filesystem without a journal, a directory-block error seen in the previous run is not seen again. The docs say to keep the state directory on ext4, xfs or btrfs.
    - Caches filled by an older ratarmount were never synced, and the base and the user's own lowers are outside every check (§5.13).
    - No unprivileged test makes writeback fail. T8 drives the supervisor's reaction through the Fake, and the kernel side is its documented contract (row 28).
